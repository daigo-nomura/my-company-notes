# アイデア精査レポート — 2026-11-25

## 総評

今回の収集では、EigoCheckの直接延長線（AI英語添削の差分可視化）、業界インサイダー優位を活かせる運送業向け傭車管理、そしてApp Store空白地帯の個人塾月謝管理という3つの異なるベクトルが浮かび上がった。いずれも「大手が対応しない小さな痛点」を狙う構造で、ソロ3ヶ月MVP・ライセンス不要という条件を全て満たす。ただし運送業向けは初期ユーザー獲得に業界コネクションが必要な点で、他の2件より営業難度がわずかに高い。

## 🥇 第1位: EigoCheck 差分可視化＋理由解説アップデート（または姉妹アプリ「EigoCheck Notes」）

**総合スコア: 83/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | 既存のEigoCheckコードベースに差分表示ロジック（NSAttributedString等）と理由解説プロンプトを追加するだけ。新規アプリ開発より格段に簡単 |
| 市場規模 | 15/20 | 日本の英語学習者は数百万人。ただしキーボード拡張型は能動的DLが難しく、AppStoreのメタデータ最適化が重要 |
| 競合の少なさ | 17/20 | 「キーボード拡張型」×「差分可視化」×「理由解説（日本語）」の組み合わせは現状ほぼ存在しない。UGUIS.AIは試験特化で棲み分けできる |
| EigoCheckとの相乗効果 | 20/20 | 完全なEigoCheckの機能拡張。既存コード・ユーザー・AppStore評価・レビューをそのまま活用。ゼロから始める必要がない |
| マネタイズ可能性 | 13/20 | 現在のEigoCheckの課金状況次第。フリーミアム→月額¥480〜¥980への誘導が現実的。「理由解説は有料」という機能分割が自然 |

**なぜ今のオーナーに向いているか:**
EigoCheckの開発で既にiOSキーボード拡張、OpenAI API連携、テキスト処理のコードが揃っている。新規プロダクト開発ではなく「既存資産の価値向上」なので工数が格段に少ない。日本語ユーザー向けという得意分野をそのまま活かせる。競合分析も既にEigoCheck開発時に実施済みのはず。

**MVP設計案:**
- 最小機能: ①修正前後を赤字/緑字で並べて表示（差分ハイライト）②各修正に1行の日本語解説を付ける（例：「より自然なビジネス表現です」）
- 技術スタック: SwiftUI + iOS Keyboard Extension（既存）+ OpenAI GPT-4o API（プロンプト改修のみ）
- 想定工数: 2〜4週間（差分表示UI: 1週間、プロンプト改修+テスト: 1〜2週間、AppStore審査: 1週間）
- 最初の収益化方法: 「理由解説機能」を月額¥480のサブスクに限定。フリー版は添削のみ。既存ユーザーへのアップグレード訴求

**リスク・注意点:**
- EigoCheckのユーザー規模が小さい場合、既存ユーザーだけでは収益化が難しい。新規集客施策も並行して必要
- OpenAI API料金が嵩む可能性。理由解説はトークン数が増えるため、使いすぎ制限の実装が必要
- 競合（特にDuolingo等大手）が類似機能をリリースした場合、差別化が難しくなる

## 🥈 第2位: 傭車・外注管理ミニアプリ「ヨシャリ」（仮）

**総合スコア: 74/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | CRUD+PDF出力+CloudKitで3ヶ月以内のMVP可能。複雑な地図・リアルタイム機能は不要 |
| 市場規模 | 14/20 | 国内中小運送会社は約6万社。10〜50台規模が大半。ただしBtoB SaaSの初期ユーザー獲得に業界コネが必要 |
| 競合の少なさ | 20/20 | App Storeで傭車管理専用アプリはほぼ存在しない。これは確認済みの空白 |
| EigoCheckとの相乗効果 | 3/20 | 全く異なる市場・ユーザー層。コードもスキルも流用できない。ゼロスタート |
| マネタイズ可能性 | 22/20（→補正して17/20）| 法人向け月額¥3,000〜¥5,000/社なら30社で月¥9万〜¥15万。傭車費削減効果が明確で価格交渉しやすい |

**なぜ今のオーナーに向いているか:**
デジタコ×運行管理システムのメーカー勤務というインサイダー知識が最大の武器。競合が少ない空白領域に「業界を知っている人間が作ったアプリ」として入れる。勤務先の取引先（中小運送会社）を初期ユーザーとしてアプローチできる可能性がある（本業との兼業注意が必要だが）。

**MVP設計案:**
- 最小機能: ①傭車先会社マスタ管理②案件登録（日付・ルート・単価・傭車先）③月次集計・PDF出力（請求照合用）
- 技術スタック: SwiftUI + CloudKit（マルチデバイス同期）+ PDFKit（請求書出力）
- 想定工数: 10〜12週間（データモデル設計:2週間、CRUD UI:4週間、PDF出力:2週間、テスト+AppStore:2週間）
- 最初の収益化方法: 月額¥2,980/社（個人経営の中小運送）。最初の5社は無料モニター、フィードバックをもとに改善後有料化

**リスク・注意点:**
- 本業（デジタコメーカー）との利益相反になる可能性。就業規則の副業規定を確認すること
- 初期ユーザー獲得が最大の壁。AppStore経由ではなく、業界人脈を使った直接アプローチが必要
- 中小運送会社のオーナーは「アプリ操作が苦手」なケースが多い。UI設計のシンプルさが命

**総合スコア: 72/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | 生徒管理+月謝記録+振込確認という機能は全てCRUD。SwiftUI+iCloudで2ヶ月で完成できる |
| 市場規模 | 13/20 | 国内個人塾・家庭教師は数万人規模。ただし単価の低い学生アルバイト家庭教師は課金しない。正社員・フリーランス塾講師に絞ると小さくなる |
| 競合の少なさ | 19/20 | AppStore検索「月謝管理」「塾 管理」でヒットするアプリはほぼ存在しない（2026年現在）。freeeやマネーフォワードは競合にならない |
| EigoCheckとの相乗効果 | 5/20 | 市場もコードも異なる。ただし「日本語ユーザー向け」「シンプルUI設計」という開発哲学は共通 |
| マネタイズ可能性 | 17/20 | 月額¥480〜¥980で成立。塾講師は本業で月収があり、¥500/月の出費は許容範囲。100人課金で月¥5万〜¥10万 |

**なぜ今のオーナーに向いているか:**
EigoCheck開発と同じ「日本語ユーザー向けシンプルツール」の文脈で作れる。競合がほぼゼロで、App Store SEO（キーワード「月謝管理」）だけで上位表示できる可能性が高い。機能を絞ればMVPを2ヶ月以内に完成できる。

**MVP設計案:**
- 最小機能: ①生徒一覧（名前・学年・科目）②月次月謝額設定③振込確認チェックボックス（入金/未入金）④月次集計（今月の入金額・未入金人数）
- 技術スタック: SwiftUI + CoreData（ローカル）+ iCloud Sync（オプション）
- 想定工数: 6〜8週間（データモデル:1週間、CRUD UI:3週間、月次集計表示:1週間、AppStore:1週間）
- 最初の収益化方法: 無料（〜5名）、月額¥480（6名〜）のフリーミアム。家庭教師の知人にベータテスト依頼

**リスク・注意点:**
- 市場規模が小さい。100人課金で月¥5万はリアルだが、天井が低い。EigoCheckとの並行開発が必要
- 月謝管理は「紙でいい」「LINEでいい」と思っている人も多く、デジタル化への啓蒙コストがかかる
- 「月謝管理アプリ」というカテゴリが認知されていないため、AppStore発見率が低い可能性
