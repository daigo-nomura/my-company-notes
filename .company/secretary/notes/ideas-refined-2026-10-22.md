## 🥇 第1位: 中小運送向け傭車管理アプリ「HayashaSan（仮）」

**総合スコア: 84/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUI + REST API（Firebase or Supabase）で実装可能。UIはシンプルなフォーム型。傭車会社マスタ・依頼記録・月次精算の3画面構成でMVP完成 |
| 市場規模 | 15/20 | 日本の運送事業者は約6万社（国交省統計）。10〜50台規模が中心。月額5,000〜1万円で100社獲得なら月50〜100万円。ただし法人営業が必要 |
| 競合の少なさ | 19/20 | 傭車管理単体のアプリはApp Store・Google Playでほぼ皆無。大手TMS内の一機能として存在するが、独立した軽量アプリがない |
| EigoCheckとの相乗効果 | 8/20 | 直接の相乗効果はなし。ただし「業界特化シンプルツール」という開発哲学は同じ |
| マネタイズ可能性 | 24/20（上限20） → 20/20 | 法人向けで経費計上可能。月5,000〜1万円の設定は運送会社にとって「ガソリン代の誤差」レベル。2024年問題でデジタル化プレッシャーが最高潮。6ヶ月以内に10社獲得（月5〜10万円）は現実的 |

**なぜ今のオーナーに向いているか:**
- 業界インサイダーとして「傭車管理がFAX・電話・Excel」という痛点を自分自身が日常業務で体験している
- 初期顧客を勤務先・同業他社の知人から直接獲得できる（コールドアウトリーチ不要）
- 競合が大手TMSしかなく、「シンプルで安い」だけで差別化できる

**MVP設計案:**
- 最小機能: ①傭車会社マスタ登録 ②便ごとの傭車依頼記録（日付・ルート・金額・ドライバー名） ③月次集計・PDF出力
- 技術スタック: SwiftUI（iOS）+ Supabase（バックエンド・DB）+ PDF生成（PDFKit）
- 想定工数: UI設計2週間・バックエンド2週間・テスト1週間・申請1週間 = 計6週間（1.5ヶ月）
- 最初の収益化方法: 買い切り（3,000〜5,000円）でApp Store配信 → 反応を見て月額サブスクに移行

**リスク・注意点:**
- 法人営業が初期に必要（個人開発者の弱点）→ ただしオーナーは業界コネクションあり
- 運送業界はITリテラシーが低いケースがある → UI/UXのシンプルさが命
- 勤務先との利益相反に注意（同一市場で競合するサービスにならないか確認）

## 🥈 第2位: ペット海外渡航書類チェッカー「TravelPaw（仮）」

**総合スコア: 71/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + ローカルDB（国別要件データ）で実装可能。難所は国別要件の正確なデータ収集と継続的な法改正追従 |
| 市場規模 | 13/20 | 日本からの海外ペット渡航は年間数万件規模と推測（一次統計なし）。ニッチだが課金意欲は高い |
| 競合の少なさ | 18/20 | 日本語専用ツールは皆無。Paws Abroad（英語）が2025年ローンチ済みだが日本語・日本ルート未対応 |
| EigoCheckとの相乗効果 | 8/20 | 直接の流用はなし。ただし「書類の英文作成サポート」としてEigoCheckとの連携機能は後から追加可能 |
| マネタイズ可能性 | 16/20 | 買い切り1,500〜3,000円が現実的。ユーザー数が少なくても単価を上げられる。代行業者（数万円）と比較すれば割安に訴求できる |

**なぜ今のオーナーに向いているか:**
- データベース型でSwiftUI初〜中級に適している（複雑なアルゴリズム不要）
- 「英語での書類作成」でEigoCheckとの後付け連携が自然にできる
- 競合空白が証明されており、日本語という差別化が明確

**MVP設計案:**
- 最小機能: ①出発国（日本固定）×渡航先国×ペット種の選択 ②必要書類チェックリスト生成 ③各書類の期限リマインダー（通知）
- 技術スタック: SwiftUI + UserNotifications + JSONベースの国別要件DB（初期は手動メンテ）
- 想定工数: データ収集・DB設計3週間・UI実装3週間・テスト1週間・申請1週間 = 計8週間（2ヶ月）
- 最初の収益化方法: 買い切り1,500〜2,000円。渡航先5カ国（ハワイ/米本土/豪/EU/タイ）から開始

**リスク・注意点:**
- 各国の検疫要件が変わるため、要件DBの継続メンテが必要（1人では追いつかない可能性）
- 医療・渡航情報として責任問題が生じる可能性 → 「公式情報を必ず確認」という免責表示が必須
- ユーザー数が限定的（渡航する人は一生に数回）→ リピート購入が生まれにくい

## 🥉 第3位: EigoCheck横展開「ビジネスメール英文添削キーボード」

**総合スコア: 67/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | EigoCheckのコードベースをそのまま流用。ビジネスメール特化のプロンプト調整が主な追加開発 |
| 市場規模 | 14/20 | ビジネスパーソンの英文メール需要は大きい。ただしDeepL・ChatGPT等の強い競合あり |
| 競合の少なさ | 10/20 | DeepL翻訳、ChatGPT、Grammarly等の強力な競合が存在。iOSキーボード形式に絞れば数は減るが認知度が低い |
| EigoCheckとの相乗効果 | 18/20 | コード・スキル・ユーザー層が完全に重複。EigoCheckユーザーへのアップセルまたはバンドル販売が可能 |
| マネタイズ可能性 | 8/20 | 強い無料競合（DeepL等）のせいで課金ハードルが高い。「EigoCheckの上位版」として月額300〜500円なら成立の可能性 |

**なぜ今のオーナーに向いているか:**
- EigoCheckのコードベースをそのまま使えるため開発工数が最小
- EigoCheckユーザーへの直接販売でマーケティングコストゼロ
- Swift/iOS Keyboard Extensionの学習済みスキルが最大活用できる

**MVP設計案:**
- 最小機能: ①キーボード上でビジネスメール文章を選択 ②フォーマル度（カジュアル/フォーマル/超フォーマル）を指定 ③添削結果+日本語解説を表示
- 技術スタック: EigoCheckのKeyboard Extension + Prompt engineering（Claude API or OpenAI API）
- 想定工数: プロンプト設計1週間・UI調整1週間・テスト1週間 = 計3週間（最速）
- 最初の収益化方法: EigoCheckユーザーへのイントロダクション特別価格（買い切り500〜800円）

**リスク・注意点:**
- DeepL・ChatGPT等の強力無料競合が常に存在する
- 差別化が「キーボード形式」だけでは薄い → 日本語解説の質と速度が鍵
- EigoCheckが先にリリースできていない場合、ベースが存在しない
