# アイデア精査レポート — 2026-08-01

## 総評

2026年8月時点の収集で特に目立つのは「既存プラットフォームの管理機能が業務に追いついていない」という不満が複数業種で確認されたこと。ハンドメイド作家のExcel自作管理、運送会社の紙日報・FAX傭車精算、個人塾の手書き台帳など、数百万ユーザーが課金サービスを使わずに代替手段で我慢しているセグメントが残っている。英語学習アプリ市場ではDuolingo MaxのAI機能拡張で「会話AI」が差別化軸から外れつつあり、EigoCheckは「書く英語の精度」に集中することで棲み分けが強化される。

## 🥇 第1位: 英語日記フィードバックアプリ（EigoDiary）

**総合スコア: 89/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | EigoCheckのキーボード拡張Extension・OpenAI/Claude API連携・添削UIをほぼそのまま転用可能。日記入力UI＋添削フィードバック表示で追加実装は最小限 |
| 市場規模 | 16/20 | 英語学習者（日本だけで推計1,500万人以上）のうち「書く練習がしたい」層はDuolingo離脱者＋受験英語卒業者に大量存在。日記習慣はアプリ継続率が高い |
| 競合の少なさ | 18/20 | 「自由英作文を書くと即座に添削＋語彙提案」のアプリはApp Storeで1〜2件のみ。DuolingoもSpeakも「話す」特化で「書く日記の添削」は空白 |
| EigoCheckとの相乗効果 | 20/20 | 既存ユーザーへの横展開が最も自然。EigoCheckで英文を書く習慣がついたユーザーが「日記でも使いたい」と感じるフロー。コードの90%以上が流用可能 |
| マネタイズ可能性 | 17/20 | 月額900〜1,500円（Duolingo Super相当）でのフリーミアム。7日間無料→月額課金が最も定番。6ヶ月以内に月3〜5万円は現実的（EigoCheckユーザーへのクロスセルだけで100〜300人獲得できれば達成） |

**なぜ今のオーナーに向いているか:**
EigoCheckで培ったSwiftUI・APIキーボード拡張・添削エンジンが全て流用できるため、実質「EigoCheckの第2プロダクト」として3ヶ月以内にMVPリリースが最も現実的。既存ユーザーへのクロスセルルートがある唯一のアイデア。英語添削ドメインの知識を活かせる。

**MVP設計案:**
- **最小機能**: ① 日記テキスト入力（SwiftUI標準TextEditorで十分）、② 保存時または送信ボタン押下で OpenAI/Claude API に添削リクエスト、③ 添削結果を「修正箇所＋理由＋代替表現」で表示、④ 過去日記一覧（CloudKitで保存）
- **技術スタック**: SwiftUI + CloudKit + OpenAI API（gpt-4o-mini）or Claude Haiku（コスト最小化）。EigoCheckの既存APIクライアントコードをほぼそのまま使用
- **想定工数**: 既存コード流用でフロントエンド2〜3週間、API連携1週間、テスト・App Store申請1〜2週間。**合計：約6〜8週間**（ソロ稼働・副業ペースで3ヶ月以内に余裕）
- **最初の収益化方法**: フリーミアム。無料：1日3件まで添削、有料（月額1,200円）：無制限＋語彙レポート＋学習傾向グラフ

**リスク・注意点:**
- API費用：gpt-4o-miniなら日記1件あたり約0.3〜0.5円。月100人の有料ユーザーで月数千円のAPI費用→利益圧迫は軽微
- Duolingo Maxが同様の機能を追加した場合に差別化が困難になる。ただし「日記という自由形式の添削」はDuolingoの教材型UXとは根本的に異なる
- 継続率を上げるためにストリーク（連続投稿）機能は早期から実装すべき

## 🥈 第2位: ハンドメイド作家向け原価・在庫・注文一元管理アプリ（HandmadeBook）

**総合スコア: 72/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + CloudKit のCRUD（Create/Read/Update/Delete）が中心。PDF請求書出力が若干手間（PDFKit使用）。ソロで3ヶ月以内に完成できる規模感 |
| 市場規模 | 14/20 | minne登録作家は100万人超、Creema登録は50万人以上。ただしアクティブ出品者は数十万人規模で、月額500〜1,500円を払う層はその1割〜2割程度 |
| 競合の少なさ | 20/20 | 「原価計算＋在庫管理＋注文管理を一括管理できるハンドメイド専用アプリ」はApp Storeで直接競合ほぼゼロ。minne/Creema公式アプリは販売機能のみ |
| EigoCheckとの相乗効果 | 5/20 | ユーザー層もコードも重複なし。ただしSwiftUI・CloudKit・App Store申請スキルは完全に流用できる |
| マネタイズ可能性 | 16/20 | 月額500〜1,500円。minne/Creemaのコミュニティ（SNS・ブログ）でのバイラル拡散が期待できる。6ヶ月以内に月3万円達成のためには有料ユーザー200〜600人必要 |

**なぜ今のオーナーに向いているか:**
競合がほぼ皆無で、ターゲットユーザー（minne/Creema作家）のペインポイントが「Excelで代用中」という具体的な形で可視化されている。EigoCheckとのスキル流用度は低いが、SwiftUI＋API連携という共通の技術スタックで開発できる。

**MVP設計案:**
- **最小機能**: ① 材料費入力＋自動原価計算（利益率表示）、② 在庫数管理（商品別）、③ 注文記録（日付・販売先・金額）、④ minne/Creema手数料自動差し引き計算
- **技術スタック**: SwiftUI + CloudKit（無料枠で十分）。minne/Creema APIは非公開のため手動入力ベース
- **想定工数**: フロントエンドUI 3〜4週間、データモデル・CloudKit連携 2週間、PDF出力 1週間、テスト・申請 1〜2週間。**合計：約8〜10週間**
- **最初の収益化方法**: 買い切り（¥750〜980）または月額（¥500〜980）。Xとnoteのハンドメイドコミュニティで告知が最も効果的

**リスク・注意点:**
- minne/Creema側のAPI変更・仕様変更があっても手動入力ベースなら影響なし
- ユーザー獲得はEigoCheckの既存チャネルと無関係なので、新規SNSアカウント（ハンドメイド作家向け）の育成が必要
- 単価が低め（月500〜1,500円）なので、月3〜10万円達成には200〜700人の有料ユーザーが必要

## 🥉 第3位: 中小運送会社向け傭車管理＋日報スマホ入力アプリ（YushaLog）

**総合スコア: 72/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 14/20 | SwiftUI + REST API + PDF出力は技術的に可能。ただし「業務フロー理解＋オフライン対応＋PDF請求書フォーマット」と考慮点が多い。3ヶ月で基本機能は完成できるが、品質担保に時間がかかる |
| 市場規模 | 16/20 | 全国の運送事業者数は約6万社（うち中小が大半）。10〜50台規模の目標市場は数千社。月額1〜3万円の高単価なので少ない顧客数でも収益達成できる |
| 競合の少なさ | 20/20 | 傭車管理特化アプリはApp Storeでほぼゼロ。既存の大手システムは100万円以上のイニシャルコストで中小には敷居が高すぎる |
| EigoCheckとの相乗効果 | 2/20 | ユーザー・コードともに重複ゼロ。唯一の共通点はSwiftUI・APIスキル |
| マネタイズ可能性 | 20/20 | 月額1〜3万円/社。10社で月10〜30万円達成。BtoBは解約率が低く、一度導入されれば長期契約が見込める。6ヶ月以内に月3〜10万円は10社以下の獲得で達成可能 |

**なぜ今のオーナーに向いているか:**
業界インサイダーとして「何が本当に面倒か」「どのUIなら現場が使うか」を知っていることが最大の優位性。競合がほぼ皆無で、月額1〜3万円という高単価のため少ない顧客数でも収益目標を達成できる。勤務先の業界人脈が初期顧客の紹介につながるなら参入障壁が一気に下がる。

**MVP設計案:**
- **最小機能**: ① 傭車依頼の登録（日付・便・傭車会社・金額）、② 月次精算レポート自動生成（PDF出力）、③ ドライバー日報スマホ入力（出庫時刻・帰庫時刻・走行距離・荷物件数）、④ オフライン対応（圏外でも入力可能、後で自動同期）
- **技術スタック**: SwiftUI + Supabase（リアルタイム同期・認証）+ PDFKit。複数台からのアクセスを想定してCloudKitではなくSupabaseを推奨
- **想定工数**: 業務ロジック設計 2週間、SwiftUI 4週間、Supabase連携 1週間、PDF出力 1週間、テスト・申請 2週間。**合計：約10〜12週間**（3ヶ月でギリギリ完成可能）
- **最初の収益化方法**: 初期は勤務先業界の人脈に直接営業し1〜3社に無料提供→フィードバック→月額課金へ移行。月額9,800〜29,800円の設定が適切

**リスク・注意点:**
- 初期顧客獲得に業界人脈が不可欠。App Storeの自然検索だけでは中小運送会社への到達が困難
- 現在の本業（デジタコ・運行管理システムメーカー）との利益相反がないか確認が必要
- BtoB契約のため利用規約・個人情報取り扱い・サポート体制の整備が必要（法人向けの心理的ハードル）
