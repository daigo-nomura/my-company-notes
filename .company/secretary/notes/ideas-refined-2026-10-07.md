# アイデア精査レポート — 2026-10-07

## 総評

今回の収集では、運送業界インサイダーとしての強みを最大活用できる「傭車管理アプリ」が突出して有望。次いで、EigoCheckのコードとユーザーを流用しやすい「ビジネスメール英語添削Webツール」、そしてハンドメイド作家向け原価計算アプリが実装難易度・市場ニーズのバランスで上位に入った。AI Codexの普及でiOS開発の参入障壁が下がっており、「業界インサイダーしか知らないペイン」を持つ者が3ヶ月で作れる時代になっている。

## 🥇 第1位: 傭車・外注便 記録・精算管理アプリ（運送業向け）

**総合スコア: 84/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + CloudKit + REST APIでCRUD+計算ロジック中心。デジタコ連携不要。MVPは「傭車先・便名・日付・金額入力→月次精算表出力」だけで成立 |
| 市場規模 | 16/20 | 国内中小運送会社は約6万社。10〜50台規模がターゲット。月3,000〜5,000円×100社=月30〜50万円が6ヶ月以内に現実的 |
| 競合の少なさ | 19/20 | App Storeで「傭車管理」検索で5件以下。大手配車システムは中小には高すぎ・複雑すぎで実質空白地帯 |
| EigoCheckとの相乗効果 | 10/20 | ユーザー層もコードも共通点なし。ただしSwiftUIスキルは流用可能 |
| マネタイズ可能性 | 20/20 | 「月3,000〜5,000円なら即導入」という声が複数。IT導入補助金対象になれば初期導入ハードルも下がる。6ヶ月以内に月3〜10万円は十分達成可能 |

**なぜ今のオーナーに向いているか:**
業界インサイダーとして傭車業務の実態・用語・商慣習を知っている。これは他の個人開発者が絶対に持てない参入障壁。既存の大手システムが「高すぎる・複雑すぎる」という声を直接聞いている立場からMVPを設計できる。営業も勤務先ネットワーク経由で入りやすい。

**MVP設計案:**
- 最小機能: 傭車先登録 → 便ごとに日付・ルート・金額入力 → 月次精算表をPDF/CSVで出力
- 技術スタック: SwiftUI + CloudKit (or Firebase) + PDFKit (精算書出力)
- 想定工数: 設計2週間・実装6週間・テスト2週間 = 約2.5ヶ月
- 最初の収益化方法: 14日無料トライアル→月額3,000〜4,800円のサブスク。最初の10社は勤務先ネットワーク経由

**リスク・注意点:**
- 運送会社へのBtoB営業が必要（勤務先在籍中の副業規定を確認）
- 法令対応（運行記録の法的要件）が変わった場合のメンテコスト
- 大手が同機能を低価格で出してきた場合のリスク（ただし当面は動きが遅い）

## 🥈 第2位: ビジネスメール英語添削Webツール（EigoCheck派生・BtoB版）

**総合スコア: 79/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | EigoCheckのAPI呼び出しロジック・差分表示UIをほぼそのまま流用可能。Webアプリ版ならSwift不要・Next.js + Claude APIで2ヶ月以内にMVP可能 |
| 市場規模 | 16/20 | 日本のビジネスパーソンの英語メール需要は巨大。特に外資系・輸出企業に在籍する個人ユーザーを狙える |
| 競合の少なさ | 14/20 | DeepLやGrammarlyが部分的に競合するが「ビジネスメール特化・日本語フィードバック付き」という組み合わせは少ない |
| EigoCheckとの相乗効果 | 19/20 | コード（API呼び出し・差分表示）・既存ユーザーへのクロスセル・同じ英語添削ドメインの知見をフルに流用 |
| マネタイズ可能性 | 12/20 | 月額500〜980円のBtoCから始め、法人プランへ拡張。6ヶ月で月3万円達成はやや慎重な見方が必要（集客コストが高い） |

**なぜ今のオーナーに向いているか:**
EigoCheckで培った英語添削のドメイン知識・Claude/OpenAI API活用経験・UI設計をそのまま活用できる。EigoCheckユーザーへのクロスセルで初期ユーザー獲得コストがほぼゼロ。

**MVP設計案:**
- 最小機能: テキストエリアに英語メール貼り付け→添削結果（修正版+日本語解説）を表示→コピー
- 技術スタック: Next.js + Claude API (Haiku or Sonnet) + Vercel（ほぼゼロコスト運用）
- 想定工数: 設計1週間・実装4週間・テスト1週間 = 約1.5ヶ月
- 最初の収益化方法: 月5回無料→月額980円のサブスク（Stripe）

**リスク・注意点:**
- Grammarlyや各種AI系ツールの無料機能強化で差別化が難しくなる
- 「日本語フィードバック」という強みを前面に出し続けることが重要
- EigoCheckとのカニバリゼーションに注意（用途を明確に分ける）

## 🥉 第3位: ハンドメイド作家向け 原価計算・在庫・注文管理アプリ

**総合スコア: 73/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 19/20 | シンプルなCRUD + 計算ロジックのみ。SwiftUI + CoreData + CloudKitで2ヶ月以内にMVP完成。ネイティブ機能以外の外部依存がない |
| 市場規模 | 14/20 | BASE・Creema・minneの作家数は数十万人。ただし課金意欲が低い層が多い可能性あり |
| 競合の少なさ | 16/20 | App Storeで「原価計算 ハンドメイド」検索では5〜10件。UIが古い・スマホ最適化が不十分な既存アプリが多い |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層の重複は少ない。SwiftUIスキルのみ流用 |
| マネタイズ可能性 | 16/20 | 月額480〜980円のシンプル課金。「原価計算だけで月数百円払う」という声あり。6ヶ月で月3万円は現実的（300人×月100円換算） |

**なぜ今のオーナーに向いているか:**
実装が最もシンプルで、Swift初〜中級のソロ開発者が最も確実に3ヶ月以内にMVPを完成できる。失敗しても学習コストが低く、次のプロジェクトへの経験値になる。

**MVP設計案:**
- 最小機能: 材料登録（名前・単価・単位）→ 作品ごとに使用材料と工数を入力→ 原価・推奨販売価格を自動計算→ 一覧表示
- 技術スタック: SwiftUI + CoreData + CloudKit（iCloud同期）
- 想定工数: 設計1週間・実装5週間・テスト2週間 = 約2ヶ月
- 最初の収益化方法: 5作品まで無料→月額480円のサブスク（StoreKit 2）

**リスク・注意点:**
- ターゲットユーザーの課金意欲の確認が必要（無料ユーザーが多い可能性）
- BASEやminne公式が類似機能を取り込む可能性
- 材料費・工賃以外の複雑な計算ニーズに応えようとすると開発が膨らむ（機能を絞ること）
