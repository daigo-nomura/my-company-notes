## 🥇 第1位: 日本語音声入力→英語テキスト変換キーボード

**総合スコア: 84/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | SwiftUI Keyboard Extension（EigoCheckで実績あり）+ Whisper API for transcription + OpenAI for translation。音声処理パイプラインの追加が必要だが3ヶ月MVP は現実的 |
| 市場規模 | 16/20 | 英語学習者（推計800万人超）＋ビジネス英語ユーザー。スピークバディ500万DLが市場規模を証明。日本語→英語キーボード特化の需要は広い |
| 競合の少なさ | 17/20 | App Storeで「日本語音声入力→英語テキスト出力」のキーボード拡張はほぼ存在しない。Wispr Flowは英語専用で日本語非対応 |
| EigoCheckとの相乗効果 | 20/20 | 同一アーキテクチャ（Swift Keyboard Extension）・同一ユーザー層（日本語話者で英語を書きたい人）。EigoCheckユーザーへの横展開でゼロからの集客不要 |
| マネタイズ可能性 | 16/20 | フリーミアム（月50回無料→月額480〜980円）または買い切り1,500〜2,000円。EigoCheckのユーザーベースがあれば6ヶ月以内に月3〜5万円は現実的 |

**なぜ今のオーナーに向いているか:**
EigoCheckでキーボード拡張の実装経験があり、Whisper API・OpenAI APIの利用経験もある。同じアーキテクチャの延長線上で作れるため、0→1のリスクが最も低い。EigoCheckユーザーが「次に欲しいもの」とほぼ一致しており、既存チャネルで宣伝できる。英語学習×音声入力というProduct Hunt July 2026のトレンドにも乗っている。

**MVP設計案:**
- 最小機能:
  1. iOSキーボード拡張として起動するマイクボタン
  2. 日本語で話す → Whisper API でテキスト化
  3. OpenAI API で自然な英語に変換
  4. 変換結果を任意のテキストフィールドに貼り付け
  5. 変換履歴を10件保存
- 技術スタック: SwiftUI + Swift Keyboard Extension + AVFoundation + Whisper API + OpenAI GPT-4o mini
- 想定工数:
  - キーボード拡張の音声録音UI: 2週間
  - Whisper API 連携: 1週間
  - OpenAI 変換・貼り付け: 1週間
  - App Store 審査対応: 1〜2週間
  - 合計: 約6〜7週間（余裕を持って3ヶ月以内）
- 最初の収益化方法: EigoCheckのアプリ内告知→買い切り1,500円 or フリーミアム（月50回無料→月額680円）

**リスク・注意点:**
- App Store の Keyboard Extension 審査は通常より厳しい（EigoCheckで経験済みなので問題ないはず）
- Whisper API のコストが使い放題ユーザーには積み上がる → 無料回数制限は必須
- 「英語変換の質」で差が出る。OpenAI GPT-4o mini で十分か要検証（テスト必要）
- Apple Intelligence が iOS 19 で同種の機能を追加した場合に代替されるリスク（中期的な懸念）

## 🥈 第2位: 傭車管理シンプルアプリ（中小運送会社向け）

**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + Supabase（または iCloud）で CRUD 中心。複雑な機能は不要でシンプルな帳票・履歴管理。業界知識があれば仕様決めが速い |
| 市場規模 | 15/20 | 中小運送会社（全国推計5万社以上）で傭車を使う会社は半数以上。ただし BtoB 営業が必要で実際の導入数はソロでは限られる |
| 競合の少なさ | 19/20 | App Store に傭車管理専用アプリはほぼ存在しない。完全なブルーオーシャン |
| EigoCheckとの相乗効果 | 3/20 | ほぼなし。ユーザー層・技術スタックが異なる。完全な新規事業として扱う必要あり |
| マネタイズ可能性 | 17/20 | 月額3,000〜5,000円/社。50社で月15〜25万円。2026年問題の義務化ドリブンで導入の追い風あり。単価が高く少数顧客でも収益化できる |

**なぜ今のオーナーに向いているか:**
デジタコ×運行管理システムメーカー勤務のインサイダーとして「傭車管理の何が本当に面倒か」を知っている。競合が作れない「本物の業務フローに合った設計」ができる点が最大の差別化。既存の大手システムが傭車管理を軽視している隙間を突ける。

**MVP設計案:**
- 最小機能:
  1. 傭車会社マスタ登録（社名・連絡先・単価）
  2. 便ごとの傭車依頼記録（日時・ルート・傭車先・金額）
  3. 月次精算レポートのCSV出力
  4. 傭車先ごとの累計金額確認
- 技術スタック: SwiftUI + Supabase（PostgreSQL + Auth）+ CSV Export
- 想定工数:
  - データモデル設計＋基本CRUD: 3〜4週間
  - 月次レポート＋CSV出力: 2週間
  - UI調整・App Store 申請: 2〜3週間
  - 合計: 約2〜2.5ヶ月
- 最初の収益化方法: 勤務先の中小運送会社コネクション経由でβ版を5〜10社に無料提供 → 月額3,000円で正式リリース

**リスク・注意点:**
- BtoB 営業が必須。Web マーケティングだけでは集客困難。勤務先の人脈をどこまで使えるかが鍵
- 勤務先との利益相反リスク（同業向けツールを個人で作ることが就業規則に引っかからないか確認が必要）
- 中小運送会社の IT リテラシーが低い場合、オンボーディングコストがかかる
- 傭車先との EDI 連携を求められた場合、スコープが一気に拡大するリスク

**総合スコア: 69/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | 最もシンプルなCRUD。SwiftUI + iCloud で材料・在庫・原価計算・販売管理の4画面で構成可能。初〜中級者でも2ヶ月以内にMVPが出せる |
| 市場規模 | 14/20 | minneの登録作家数は100万人規模。ただし課金意欲の高い人（本業・副業として月10万円以上稼ぐ層）は全体の5〜10%程度 |
| 競合の少なさ | 18/20 | App Storeに「ハンドメイド原価計算専用」アプリはほぼない。汎用の在庫管理アプリはあるが使いにくいとの声多数 |
| EigoCheckとの相乗効果 | 5/20 | ほぼなし。EigoCheckのユーザーとの重なりが小さい |
| マネタイズ可能性 | 14/20 | 買い切り980〜1,480円 or フリーミアム（無料：5品目まで / 有料：無制限）。月3万円達成には数百本のダウンロードが必要 |

**なぜ今のオーナーに向いているか:**
実装難易度が最も低く「3ヶ月でリリースして収益化を体験する」という目標を最も確実に達成できる。App Store に競合がほぼなく、SEO・ASO でも上位に入りやすい。minne/Creema の大規模な既存ユーザーベースへのリーチが可能。

**MVP設計案:**
- 最小機能:
  1. 材料マスタ（材料名・単価・在庫数）
  2. 商品登録（材料の組み合わせ × 数量 → 原価自動計算）
  3. 販売価格設定 → 利益率の自動表示
  4. minne/Creema への販売数手動入力 → 在庫自動減算
  5. 月次売上・利益サマリー
- 技術スタック: SwiftUI + Core Data（または iCloud） 
- 想定工数: 4〜6週間（最小構成）
- 最初の収益化方法: 買い切り980円（Appリリース直後）→ minne のハッシュタグ・X Twitter でのゲリラ告知

**リスク・注意点:**
- 課金率が低い可能性（ハンドメイド作家層は節約志向が強い）
- minne/Creema との公式 API 連携は審査が必要 → MVP は手動入力で割り切る
- EigoCheck とのシナジーがないため、既存ユーザーベースを活かせない
- 機能追加の要望（発送管理・メルカリ連携等）が来た場合、スコープが広がるリスク
