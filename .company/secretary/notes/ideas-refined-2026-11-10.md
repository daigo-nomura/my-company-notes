# アイデア精査レポート — 2026-11-10

## 総評

今回は日本発・海外発の双方で「小さく確実に稼ぐ」路線に合致するアイデアが複数確認できた。特に Instagram DM 自動化ツールの月25万円達成事例（月額¥4,000×50人）と、Zenn での確認申告補助マイクロSaaS（月額¥1,350）は「このオーナーが3ヶ月で到達できるルートの実例」として重要。運送業界インサイダーとしての知識を活かした傭車管理アプリは競合が少なく、業界ネットワークを最初の10社獲得に活用できれば中期的に最も安定した収益源になり得る。

## 🥇 第1位: 傭車管理シンプルアプリ（中小運送会社向け）

**総合スコア: 78/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + CloudKit でMVP可能。傭車リスト・発注記録・月次精算明細のCRUDで基本機能は完成。PDF出力（PDFKit）も標準機能で対応可。3ヶ月以内に完成できる規模 |
| 市場規模 | 15/20 | 日本の運送会社（トラック10〜50台）は約5万社以上存在。傭車を使う会社は多い。ただし個社あたりの導入決定に時間がかかるBtoB特有の課題あり |
| 競合の少なさ | 18/20 | App Storeで「傭車管理」の日本語特化シンプルアプリはほぼ存在しない。大手TMSの一機能として埋もれているか、高額パッケージしかない |
| EigoCheckとの相乗効果 | 10/20 | 英語学習とは離れているため直接の相乗効果は薄い。ただしコード（CloudKit・PDF出力・課金）は流用可能 |
| マネタイズ可能性 | 19/20 | 月額¥3,000〜¥5,000/社×20社=月6〜10万円が6ヶ月以内目標。業界コネクション経由で最初の5〜10社は取れる可能性が高い。チャーンが低いBtoB SaaS |

**なぜ今のオーナーに向いているか:**
運送業界インサイダーとして傭車管理の実態（電話・FAX・Excel・月末照合の手間）を身をもって知っている。競合不在の領域で「業界人が作ったツール」という信頼感が最初の顧客獲得に直結する。最初の顧客は既存の業界人脈から獲得できるため、コールドコールやSEO依存のマーケティングが不要。

**MVP設計案:**
- 最小機能:
  1. 傭車会社の登録・管理（会社名・連絡先・単価）
  2. 便ごとの傭車発注記録（日付・区間・傭車先・金額）
  3. 月次精算明細PDF出力（FAX/メール送信用）
  4. シンプルなダッシュボード（今月の傭車費用合計）
- 技術スタック: SwiftUI + CloudKit（バックエンドゼロ・データ同期） + PDFKit（PDF生成）
- 想定工数: 2ヶ月でMVP完成（1ヶ月設計+実装、2週間テスト、2週間App Store審査）
- 最初の収益化方法: 月額¥3,000/社（freemium：5件まで無料、以降有料）。TestFlightで先行ユーザー10社獲得→収益化

**リスク・注意点:**
- BtoB 導入決定に時間がかかる（担当者→経営者の承認フロー）
- 運送会社のスマートフォン活用度にばらつきがある
- 「紙・電話で困っていない」という現状維持バイアス層への説得コスト
- 点呼記録などの法的要件が絡む機能は最初から除外すること

## 🥈 第2位: フリーランス確定申告レシートOCRアシスト（個人事業主向け）

**総合スコア: 76/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | Vision framework（iOS標準）でOCR無料。freee/マネーフォワードAPIへの連携はPhase2に回してもよい。最小版は「撮影→仕訳候補提示→手動確認」で完結。2ヶ月以内にMVP可能 |
| 市場規模 | 17/20 | 日本の個人事業主・フリーランス約440万人（国税庁調べ）。毎年2〜3月の確定申告期が需要ピーク。ToC向けなのでBtoBより市場規模は大きい |
| 競合の少なさ | 12/20 | freee・マネーフォワード・弥生クラウドなど強い競合が存在。ただし「シンプルすぎるくらいシンプルな版」「特定職種（エンジニア・デザイナー・ライター）特化版」なら差別化可能 |
| EigoCheckとの相乗効果 | 13/20 | EigoCheckユーザー（英語学習ユーザー）はフリーランス・個人事業主が多い可能性が高い。クロスセル先として有望。OCR技術はEigoCheckの画像入力機能にも転用可能 |
| マネタイズ可能性 | 16/20 | 月額¥480〜¥980/人で1,000人なら月50〜100万円。ただし確定申告シーズン外のチャーンが課題。nornai氏の月¥1,350実例が実現可能性の根拠 |

**なぜ今のオーナーに向いているか:**
iOS標準のVision frameworkを使うためAPI費用ゼロでスタートできる。Zenn (nornai) の実例で「月¥1,350で継続課金中」が確認済み。EigoCheckで培ったiOSキーボード・テキスト処理のスキルがOCR実装にも転用できる。

**MVP設計案:**
- 最小機能:
  1. カメラ or フォトライブラリからレシート撮影
  2. Vision OCR でテキスト抽出（日付・金額・店名）
  3. 仕訳候補を3択で提示（消耗品費・交際費・通信費等）
  4. CSVエクスポート（freeeに手動インポート可能な形式）
- 技術スタック: SwiftUI + Vision framework (OCR・無料) + CoreData（ローカル保存）
- 想定工数: 1.5ヶ月でMVP（確定申告シーズン前の1月リリースを狙う）
- 最初の収益化方法: 無料で20件まで、以降は月額¥480でサブスクリプション

**リスク・注意点:**
- 確定申告シーズン外（4〜12月）のアクティブユーザー確保が課題
- freee・マネフォが「超シンプル版」でリリースしてきた場合のリスク
- 日本語レシートのOCR精度（手書きレシートは難しい）

## 🥉 第3位: ペット×国際渡航 手続きチェックリストアプリ（日本語特化）

**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | 国×ペット種×渡航方向のJSONデータ + SwiftUI リスト表示。外部API不要。チェックリスト生成ロジックは単純な条件分岐。2ヶ月以内にMVP可能 |
| 市場規模 | 13/20 | 年間海外渡航者の中でペット同伴者は一定数いるが、ニッチ。ただし失敗コスト（最長180日隔離）が高いため情報への支払い意欲は高い |
| 競合の少なさ | 17/20 | 日本語特化の「国×ペット種×年度別 手続きチェックリスト」iOS アプリはほぼ存在しない。英語圏のサービスは存在するが日本語対応が弱い |
| EigoCheckとの相乗効果 | 8/20 | 直接の相乗効果は薄い。英語の手続き書類を読む際に英語補助として連携はあり得るが、弱い |
| マネタイズ可能性 | 15/20 | 1回限りの渡航準備ニーズが多いため買い切り¥480〜¥980が適している。リピートは少ないが、「失敗すると180日隔離」という高い失敗コストが購入を後押し |

**なぜ今のオーナーに向いているか:**
外部API不要・データ管理ベース・SwiftUI最小機能でMVP可能。競合が少なく「作れば誰かに刺さる」確実性が高い。コンテンツさえ正確であれば技術的難易度は低い。

**MVP設計案:**
- 最小機能:
  1. 渡航先国・ペット種（犬/猫）・渡航日の入力
  2. 国×種ごとのチェックリスト生成（マイクロチップ・ワクチン・抗体検査・待機期間等）
  3. 各ステップにタイムライン（「渡航の○日前までに」）を表示
  4. チェック済み状態の保存（CoreData）
- 技術スタック: SwiftUI + JSON データファイル（国別要件）+ CoreData
- 想定工数: 1.5ヶ月（コンテンツ収集に0.5ヶ月、実装1ヶ月）
- 最初の収益化方法: 買い切り¥480。対応国数を増やす有料追加パックも検討

**リスク・注意点:**
- 情報の正確性・更新コストが継続的に発生（法改正への追従が必要）
- 誤情報で入国拒否→ユーザーへの損害賠償リスク（免責事項の明記が必須）
- 渡航先国数が少ないと使えるユーザーが限定的（最初は日本→米・豪・ハワイ・英の4ルートに絞る）
