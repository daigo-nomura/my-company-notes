## 🥇 第1位: 日本語「敬語チェッカー」iOSキーボード拡張

**総合スコア: 85/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | EigoCheckのKeyboardExtension実装をほぼそのまま流用。変更はOpenAIのシステムプロンプトと判定ロジックのみ。MVPは1〜2ヶ月以内に完成できる。SwiftUI/iOS初〜中級でも確実に作れる |
| 市場規模 | 14/20 | 就活生（毎年40万人）・新入社員・外国人ビジネスパーソン（日本在住200万人）が主ターゲット。英語学習市場よりニッチだが検索需要は確実にある。「敬語 チェック」「ビジネス敬語 正しい」の検索ボリュームは安定して高い |
| 競合の少なさ | 18/20 | iOSキーボード型の日本語敬語チェッカーはほぼ空白。Webツール（LEAP-MEの敬語変換ツール等）は存在するが、あらゆるアプリ内で動作するキーボード型は確認できない。App Storeで「敬語」で検索しても日本語添削特化のキーボードアプリは見当たらない |
| EigoCheckとの相乗効果 | 19/20 | KeyboardExtension実装・OpenAI API連携・サブスク課金・App Storeリリースフローがほぼ100%流用可能。EigoCheckのユーザー（英語を書く日本語ネイティブビジネスパーソン）は「日本語の敬語も不安」な層と高度に重複する。クロスセル・バンドル販売が成立する |
| マネタイズ可能性 | 16/20 | 就活シーズン（3〜5月、9〜11月）の集中ダウンロードが見込める。月額300〜480円のフリーミアム設計で、有料転換率5%・月間新規DL500件なら月3〜5万円MRRを6ヶ月以内に達成できる現実的な水準。EigoCheckとのバンドルプランで客単価向上も可能 |

**なぜ今のオーナーに向いているか:**
EigoCheckで既に最も技術的に難しい部分（KeyboardExtension、OpenAI API連携、App Storeサブスク課金）を実装済み。新規アイデアの開発コストが「プロンプトとUIのカスタマイズ」程度に圧縮される。日本人特有の英語ミスを熟知しているオーナーは、日本人の敬語ミスパターンも業務経験から熟知しているはず。「EigoCheckのキーボードを使っていて、日本語版もあれば嬉しい」というユーザーの声に直接応えられる。

**MVP設計案:**
- 最小機能:
  1. キーボード拡張として動作（あらゆるアプリ内テキスト入力に対応）
  2. 選択テキストまたは入力中のテキストをOpenAI APIに送信
  3. 「尊敬語・謙譲語・丁寧語の誤用」「ビジネスメールNGワード（「了解です」等）」を検出・修正案を提示
  4. 修正案の「理由・解説」を日本語で表示（「なぜこの表現がNGか」を学習できる）
  5. 週次の「ありがちなミス集計」をウィジェット表示
- 技術スタック: SwiftUI + KeyboardExtension + OpenAI GPT-4o mini（低コスト）+ CloudKit（ユーザー設定保存）+ StoreKit 2（サブスク）
- 想定工数: Month 1: KeyboardExtension/UI移植（EigoCheckから転用）、Month 2: プロンプトチューニング・NGワードDB整備・TestFlight、Month 3: App Storeリリース・フリーミアム設計最終調整
- 最初の収益化方法: 無料版（月5回チェックまで）→ Proプラン月額480円（無制限＋詳細解説＋ビジネスメールテンプレート）。EigoCheckとのバンドルプラン（両方で月額680円）を早期に設定してクロスセル

**リスク・注意点:**
- OpenAI APIの誤判定リスク：敬語は文脈依存が強く、固有名詞や業界用語を誤検出する可能性がある。「提案」として表示し「正解を断言しない」UIにすることで信頼性を担保する
- 市場規模の季節性：就活・入社シーズンに依存するため、年間を通じたDAUの安定性は未知数。月次・継続学習機能で年間利用を促す設計が必要
- 「ChatGPTに貼り付ければ無料でできる」という代替行動：キーボード型でアプリを跨がずチェックできるという体験価値を訴求ポイントにする

## 🥈 第2位: 軽貨物ドライバー向け超シンプル日報アプリ

**総合スコア: 73/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + CloudKit（オフライン対応）+ OpenAI API（音声→日報テキスト変換）。GPS走行距離の自動記録はCoreLocation。大半の機能が標準フレームワークで実装できる。Month 1: 基本日報入力UI、Month 2: GPS連携+音声入力、Month 3: PDF出力+クラウド同期。3ヶ月MVP可能 |
| 市場規模 | 17/20 | 全国25万人の軽貨物個人事業主（2025年4月から日報保存義務化）が全員ターゲット。現在の主要競合K-LINKの月額1,000円/人という価格設定が「高い・使いにくい」と評判が悪い。義務化により「アプリなしは法律違反」という強制力があり、BtoCでも購入動機が強い |
| 競合の少なさ | 15/20 | K-LINKというプレイヤーが存在する（月1,000円/人）。ただし「機能が多すぎて重い」「UIが使いにくい」という不満が多く、シンプル版への乗り換え需要が存在する。App StoreとGoogle Playで「軽貨物 日報」で検索すると競合は限られており、2〜3位以内には入れる |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層は全く別（軽貨物ドライバー vs 英語学習者）。ただしSwiftUI・OpenAI API連携・CloudKit・App Storeリリースフローの知識は完全に流用できる。技術的流用度は高いが、ユーザー・コード・ブランドの共有はゼロ |
| マネタイズ可能性 | 17/20 | 月額500〜800円（K-LINKの半額以下）で訴求。義務化ドライバーがあるため「使わなければ違反」という強制力がある。有料ユーザー100人で月5〜8万円MRR達成。軽貨物組合・SNS（Xの軽貨物ドライバーコミュニティ）を通じた口コミ拡散が有効 |

**なぜ今のオーナーに向いているか:**
運送業界インサイダーとして「軽貨物日報に何を書く必要があるか」「現場ドライバーが何を面倒に思うか」「既存K-LINKのどこが嫌われているか」を競合開発者より深く理解している。業界用語・書類フォーマット・法令要件への精通は最大の差別化武器で、プロダクトの細部に宿る。

**MVP設計案:**
- 最小機能:
  1. 出発時刻・帰着時刻のワンタップ記録
  2. 走行距離の自動計算（GPS or 手入力）
  3. 配送先・荷物内容の音声入力→OpenAIでテキスト整形
  4. 日報のPDF出力（義務化要件を満たすフォーマット）
  5. 30日分のデータをCloudKitに保存（法定保管義務対応）
- 技術スタック: SwiftUI + CoreLocation + AVFoundation（音声入力）+ OpenAI Whisper API + CloudKit + PDFKit
- 想定工数: Month 1: 基本UI（時刻・距離入力、データ保存）、Month 2: 音声入力→テキスト整形・PDF出力、Month 3: TestFlight・軽貨物ドライバーXコミュニティでのBeta募集・App Storeリリース
- 最初の収益化方法: 無料版（30日間無料体験）→ 月額480円（無制限記録+PDF出力+クラウド同期）。年払い3,980円（約33%オフ）でLTV最大化

**リスク・注意点:**
- K-LINKとの機能競争：価格で勝てても「会社から強制指定された業者（K-LINK）しか認めない」という雇用主側の縛りがある場合がある。個人事業主向けに特化して「自分の仕事は自分で管理」の訴求が重要
- Androidユーザーが多い：軽貨物ドライバーはiOS比率が低い可能性がある。まずiOS版でPMF検証後、React Native等でAndroid版を追加するロードマップが現実的
- 法令改正リスク：義務化の内容・フォーマットが変更された際の追従コストが発生する

## 🥉 第3位: ハンドメイド作家向け在庫・原価計算アプリ（複数EC連携）

**総合スコア: 62/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 14/20 | SwiftUI単体でUIは作れる。最大の難関はminne/CreemaのAPIが外部開放されているかどうか。minne APIは存在するが公開APIは限定的で、Creemaは外部API非公開の可能性が高い。API連携なしの「手動同期＋通知」でもMVP成立は可能だが差別化が弱まる |
| 市場規模 | 15/20 | minneの登録作家数100万人超。ただし「有料アプリを使うリテラシー層」は全体の5〜10%程度とみられる。月額500円でも1,000人有料ユーザー獲得には相応の時間がかかる。ターゲット絞り込みが重要 |
| 競合の少なさ | 16/20 | App Storeで「ハンドメイド 在庫」で検索すると「サッカノカンリ」「CreateMemo」など数本のみ。在庫連携・原価計算・複数EC対応の組み合わせに特化した競合はほぼない |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層・コード・スキル・ブランドの共有はほぼゼロ。完全に新規市場への参入となる |
| マネタイズ可能性 | 13/20 | 月額500〜780円で訴求できるが、ハンドメイド作家はコスト意識が高く無料ツール（自作Excel）との比較にさらされる。100人有料ユーザーで月5〜7.8万円だが、獲得に6ヶ月以上かかる可能性がある |

**なぜ今のオーナーに向いているか:**
運送業界インサイダーという強みが活かせない領域であり、EigoCheckとの相乗効果もない。技術的には問題なく作れるが、「なぜオーナーが作るべきか」という業界理解・ユーザー近接性の根拠が薄い。第3位としたのは「競合が少なく痛点が明確」という市場機会は本物だからだが、EigoCheckとの相乗効果がゼロである点でオーナーの優先度は下げるべき。

**MVP設計案:**
- 最小機能:
  1. 作品登録（名前・写真・材料費・工賃・販売価格）
  2. 原価率・粗利益の自動計算（手数料率をminne/Creema/BASEで設定可能）
  3. 販売記録の手動入力＋在庫数の自動デクリメント
  4. 月次売上サマリー（どの作品が儲かっているか一覧）
  5. 在庫ゼロアラート通知
- 技術スタック: SwiftUI + CoreData（ローカル保存）+ CloudKit（バックアップ）。APIはV1では手動入力でMVP。V2でminne API連携を検討
- 想定工数: Month 1: 作品登録・原価計算UI、Month 2: 販売記録・在庫管理・月次レポート、Month 3: TestFlight・minneコミュニティでBeta募集・リリース
- 最初の収益化方法: 無料版（作品登録10点まで）→ Proプラン月額500円（無制限＋CSV出力＋月次レポート詳細）

**リスク・注意点:**
- minne/Creema API非公開リスク：自動在庫同期ができない場合、「Excelより少しマシ」というポジションに留まり差別化が弱い
- ターゲットの可処分所得が低い：ハンドメイド作家は副業・趣味の延長が多く、月額課金への抵抗が強い層が多い
- 先行者との比較：「CreateMemo」「サッカノカンリ」と価格・機能で差別化できるか要検証
