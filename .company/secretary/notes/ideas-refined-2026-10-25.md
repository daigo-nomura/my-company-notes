## 🥇 第1位: 傭車管理アプリ「ユーシャログ」（仮）

**総合スコア: 81/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + Supabase（バックエンド）で3ヶ月MVP可能。CRUD中心。複雑なアルゴリズムは不要。ただしBtoBなので顧客獲得（営業）にも時間が必要 |
| 市場規模 | 15/20 | 日本の中小運送会社（10〜50台規模）は全体の8割超。数万社が対象。ただしITリテラシーが低い層が多く、獲得コストがBtoCより高い |
| 競合の少なさ | 19/20 | 傭車管理に特化したiOSアプリは日本語でほぼゼロ。大手TMS付随機能しか存在しない。これが最大の優位点 |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層・スキルセット（Swift）は共通だが、英語学習×運送業は全く異なる領域。既存ユーザーへの横展開はできない |
| マネタイズ可能性 | 22/20 → 20/20 | 月額5,000〜8,000円でも「今の紙管理コスト」と比べると安い。10社導入で月5〜8万円。6ヶ月以内に月3万円は達成可能圏内 |

**なぜ今のオーナーに向いているか:**
オーナーはデジタコ・運行管理システムのメーカー勤務という唯一無二のバックグラウンドを持つ。現場の言葉（傭車・運行指示・改善基準告示）を理解している開発者は他の個人開発者にはほぼいない。これは「作れる × 売れる」の両方で機能する強烈な参入障壁。

**MVP設計案:**
- 最小機能:
  1. 傭車会社マスタ登録（会社名・連絡先・単価）
  2. 依頼記録（日付・便名・傭車先・荷主・金額）
  3. 月次集計（傭車ごとの支払い総額自動計算）
  4. PDF出力（月末の支払明細書として使用）
- 技術スタック: SwiftUI（iOSアプリ）+ Supabase（バックエンド：認証・DB）+ PDFKit
- 想定工数: 設計2週間 + 実装6週間 + テスト2週間 = 約2.5ヶ月でMVP
- 最初の収益化方法: 月額3,000〜5,000円のサブスクリプション（14日間無料トライアル付き）

**リスク・注意点:**
- 中小運送会社経営者・配車担当へのリーチ手段が必要（個人向けApp Storeだけでは届きにくい）→ 物流メディア・業界SNSへの投稿、LinkedInでの発信が有効
- 法改正（実運送体制管理簿の義務化等）を機能に反映し続ける維持コストが発生する
- 最初の数社は無料〜低価格での実証利用（ベータテスト）を想定すべき

## 🥈 第2位: 語学フレーズ手帳アプリ「EigoNote」（仮）

**総合スコア: 77/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUI + CloudKit のみ。録音（AVFoundation）・テキスト保存・カテゴリ分類が主機能。2ヶ月MVP可能。EigoCheckの既存コードをそのまま流用できる部分が多い |
| 市場規模 | 15/20 | 英語学習市場は巨大。日本人英語学習者は数千万人規模。ただしアプリ飽和市場でもある。「添削済みフレーズ保存」という軸での差別化が必要 |
| 競合の少なさ | 13/20 | Duoryのような語学ノートは存在するが英語UI。日本語特化版は少ない。ただし類似コンセプトは複数存在し、差別化の説明が必要 |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckのユーザーが「添削した英文をそのまま保存したい」というニーズに直結。同一ユーザー層、同一スキルセット、コード流用可能。App Store上でEigoCheckとセット訴求できる |
| マネタイズ可能性 | 11/20 | 英語学習アプリは無料が当たり前という価格圧力が強い。買い切り300〜500円 or 月額300〜500円が現実的。月3万円には1,000人の有料ユーザーが必要 |

**なぜ今のオーナーに向いているか:**
EigoCheckのリリース経験と既存ユーザーベースを直接活用できる唯一の選択肢。新しい市場調査不要で、既存ユーザーにベータテストを依頼できる。スキルと知識の延長線上にあり、最もリスクが低い。

**MVP設計案:**
- 最小機能:
  1. フレーズ保存（テキスト＋音声録音）
  2. カテゴリタグ付け（ビジネス・日常・旅行等）
  3. 検索・フィルタ
  4. 復習リマインダー通知
- 技術スタック: SwiftUI + CloudKit（同期）+ AVFoundation（録音）
- 想定工数: 設計1週間 + 実装5週間 + テスト2週間 = 約2ヶ月でMVP
- 最初の収益化方法: 買い切り480円 or 月額250円（EigoCheckユーザー向け割引キャンペーン）

**リスク・注意点:**
- 英語学習アプリは競合が多く、差別化の説明コストが高い
- 「EigoCheckで添削した英文を自動で保存」という連携機能なしには独立したアプリとして弱い
- 月3万円達成には多数のユーザーが必要 → EigoCheckのユーザー数次第

## 🥉 第3位: ペット×海外渡航チェックリスト生成サービス

**総合スコア: 62/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | SwiftUI or Next.js + ChatGPT API（渡航先×ペット種別のチェックリスト生成）。3ヶ月MVP可能。ただし情報の正確性確認に時間がかかる |
| 市場規模 | 12/20 | 世界市場は大きいが日本語圏の海外渡航ペットオーナーは限定的。海外赴任・移住者のニッチ市場 |
| 競合の少なさ | 16/20 | 日本語の中立的情報サービスは空白。ただし政府サイト（農水省）という無敵の競合が存在する |
| EigoCheckとの相乗効果 | 3/20 | ほぼなし。ユーザー層も技術スタックも異なる |
| マネタイズ可能性 | 16/20 | 「代行ではなく情報提供」なら初期コスト低い。チェックリスト生成の従量課金（1回200〜500円）またはサブスク（月500〜1,000円）が現実的 |

**なぜ今のオーナーに向いているか:**
競合の空白は明確で、日本語情報の不整備は実証済み。ただしオーナーのバックグラウンド（運送業・英語学習）との接点が薄い。他の2つと比べると「オーナーにしか作れない理由」が弱い。

**MVP設計案:**
- 最小機能:
  1. 渡航先国・ペット種類の入力
  2. 手続きチェックリスト生成（ChatGPT APIベース、テンプレート補完）
  3. 各手続きのリンク・参考情報
  4. チェック済みマーク保存
- 技術スタック: SwiftUI + OpenAI API + Supabase（チェックリスト保存）
- 想定工数: 設計2週間 + 実装6週間 + 情報精査2週間 = 約2.5〜3ヶ月でMVP
- 最初の収益化方法: 無料でリリース後、広告 or 有料チェックリストPDF出力機能

**リスク・注意点:**
- 規制情報の変更追跡が継続コストになる（特に各国の検疫規制は変わりやすい）
- ChatGPT APIによる情報生成は正確性の担保が難しく、誤情報リスクが高い（ペット渡航は命に関わる）
- 「無料の政府サイトで十分」と思われるとマネタイズが困難
