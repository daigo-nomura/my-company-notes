# アイデア精査レポート — 2026-10-16

## 総評

今回収集したアイデアには「情報の非対称性を解消するツール」（ペット渡航）と「汎用ツールでは手が届かないニッチ職種のシンプル業務ツール」という2つの大きな流れがある。EigoCheck開発中のオーナーにとって、既存スキル（KeyboardExtension・OpenAI API連携）が活かせる英語学習周辺領域と、業界知識を持つ運送業界の2軸が特に優位性を持つ。ただし運送業は営業コストが伴うため、純粋なiOSアプリ開発力で勝負できるペット渡航×個人塾の2つが短期収益化に向いている。

## 🥇 第1位: ペット海外渡航チェックリスト＆手続きガイドアプリ
**総合スコア: 81/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | 国別チェックリスト＋フローは複雑だが、UIはSwiftUI+JSONで実装可能。バックエンド不要で進められる。コンテンツ収集に時間がかかる点がリスク |
| 市場規模 | 15/20 | 海外駐在・移住・留学人口は数十万人規模。ただし渡航頻度が低く（一生に数回）リピート率は低い。広告・代行アフィリエイト収益モデルが必要 |
| 競合の少なさ | 18/20 | App Storeに日本語特化の国別チェックリストアプリは確認できず。PetAir JPNは代行サービス（高価）。公式情報は読みにくい。実質競合なし |
| EigoCheckとの相乗効果 | 10/20 | 直接の技術的流用は少ない。ただし「日本人向けiOSアプリ」という開発経験・ストア運営ノウハウは活かせる |
| マネタイズ可能性 | 21/20（上限20）→20 | 代行業者アフィリエイト（PetAir JPN等）+買い切り500〜980円+プレミアム（国別詳細PDF出力）の複合が有効。月3〜5万円は6ヶ月以内に達成可能と推定 |

**なぜ今のオーナーに向いているか:**
情報収集・整理がコアバリューのツールのため、AIコーディング支援を活用すれば技術力が標準でも完成できる。コンテンツ（各国の手続きルール）は公開情報から収集可能でライセンス不要。失敗コストが高い（書類不備=係留・送り返し）ため「お金を払ってでも正確な情報が欲しい」ニーズが実証されている。

**MVP設計案:**
- 最小機能: 日本→アメリカ・オーストラリアの2ルート×犬・猫チェックリスト。ステップごとのタイムライン表示（「今日から●ヶ月後にやること」形式）
- 技術スタック: SwiftUI + JSONベースのコンテンツ管理（ルール変更をJSON更新で対応）+ CloudKit（チェック状態の保存）
- 想定工数: 2ヶ月（コンテンツ収集1ヶ月 + 実装1ヶ月）
- 最初の収益化方法: 買い切り980円 + PetAir JPN等への参照リンク（アフィリエイト可能か要交渉）

**リスク・注意点:**
- 手続きルールの改定が頻繁 → コンテンツメンテナンスコストが継続的に発生
- 「間違えた情報で入国拒否された」というクレームリスク → 免責事項を明確に記載
- 渡航1回あたりの使用頻度が低い → 口コミ・SEO（Webランディングページ併設）が必須

**総合スコア: 76/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | 生徒管理+月謝計算+PDF請求書出力のみ。SwiftUI+Core Data+PDFKitで完結。3ヶ月以内MVP確実 |
| 市場規模 | 14/20 | 個人塾・家庭教師は日本で推定30〜50万人。ただし全員がアプリを探しているわけではない。認知コストあり |
| 競合の少なさ | 17/20 | App Storeで「個人塾 月謝」で3件以下と推定。汎用請求書（freee等）との比較で「教育特化の安さ」が訴求点 |
| EigoCheckとの相乗効果 | 10/20 | 技術的な直接流用は少ない。ただし「日本語特化・シンプルUI」という設計思想は共通 |
| マネタイズ可能性 | 17/20 | 月額980円×200名=19.6万円が目標ライン。freee対比「安くて使いやすい教育特化版」ポジション。6ヶ月以内に月3〜5万円達成は現実的 |

**なぜ今のオーナーに向いているか:**
機能スコープが小さく明確（生徒登録・月謝設定・請求書発行だけ）。ターゲットユーザーのペインが明確（Excelとfreeeの間）。BtoB的だが個人事業主向けなのでアプリストアで個人が購買意思決定できる。

**MVP設計案:**
- 最小機能: 生徒登録（名前・連絡先・月謝額）/ 月謝の支払い状況管理 / PDF請求書の生成・メール送信
- 技術スタック: SwiftUI + Core Data + PDFKit（標準ライブラリのみ）
- 想定工数: 1.5ヶ月
- 最初の収益化方法: 月額480円（無料は生徒3名まで）のフリーミアム

**リスク・注意点:**
- 「紙で十分」という層にはリーチしにくい → 塾向けコミュニティ（Twitter・Facebook）でのDMマーケティングが必要
- マネーに関わるため信頼性が重要 → 個人名より屋号でのリリースを検討

## 🥉 第3位: 運送ドライバー日報デジタル化アプリ（中小運送会社向け）
**総合スコア: 68/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 14/20 | 技術的には難しくないが「ドライバーが嫌がらないUI」設計が鍵。管理者側のWebダッシュボードも必要で工数増 |
| 市場規模 | 17/20 | 全国10〜50台規模の中小運送会社は数万社。法的義務化ドライブで需要は確実。市場規模は大きい |
| 競合の少なさ | 12/20 | 大手向けシステムは多数存在。「中小向けシンプル安価版」は少ないが競合が全くないわけでもない |
| EigoCheckとの相乗効果 | 6/20 | 技術的共通点はほぼなし。ただし業界インサイダーとしての知識が参入障壁になる |
| マネタイズ可能性 | 19/20 | 月額3,000〜10,000円/社×20社=6〜20万円。現職コネクションで初期顧客獲得できれば達成現実的 |

**なぜ今のオーナーに向いているか:**
業界インサイダーとして「中小が本当に困っていること」を知っている。既存の大手システムの限界を知っている。現職コネクションで初期5〜10社を無償提供→フィードバック→有料化という最速PMFが可能。

**MVP設計案:**
- 最小機能: ドライバーがスマホで日報入力（出発地・目的地・走行距離・荷物内容・備考）+ 管理者がWeb画面で確認・CSV出力
- 技術スタック: SwiftUI（ドライバー用iOSアプリ）+ Cloudflare Workers（軽量バックエンド）+ REST API
- 想定工数: 3ヶ月（iOS + Web管理画面）
- 最初の収益化方法: 初期5社無償 → 有料転換時に月額5,000円/社

**リスク・注意点:**
- 営業が必要（個人で完結しない）→ 現職コネクション必須。転職・独立とセットで考える必要あり
- 規制対応（国土交通省の点呼記録要件）の正確な把握が必要 → 間違いがあると導入企業が違反リスクを負う
- 3ヶ月で完成できるが「iOS + Web管理画面」の二面開発は工数リスクあり
