## 🥇 第1位: 傭車管理・実運送体制管理簿 iOS/Webアプリ（運送業向け）

**総合スコア: 82/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | データ入力・一覧表示・PDF/CSV出力がメイン。SwiftUI + Supabaseで完結可能。複雑なアルゴリズム不要 |
| 市場規模 | 16/20 | 日本全国の中小運送会社（10〜50台）は数万社。2025年法改正で全社が実運送体制管理簿の作成義務を負う |
| 競合の少なさ | 18/20 | App Storeで「傭車管理」専用アプリはほぼ存在しない。大手システムの1機能としてしかない |
| EigoCheckとの相乗効果 | 8/20 | コードの流用は少ないが、SwiftUI・StoreKit・App Storeリリース経験は直接活用できる |
| マネタイズ可能性 | 24/20 → **20/20** | 法改正ドリブンで「やらないといけない」業務。月額3,000〜8,000円設定で10社獲得＝月3〜8万円。100社で月30〜80万円。BtoBは解約率が低く積み上がりやすい |

**なぜ今のオーナーに向いているか:**
デジタコ×運行管理システムメーカーに勤務しているため、傭車管理の業務フロー（発注→運行→精算→実運送体制管理簿への記録）を誰よりも深く理解している。競合他社や外部のエンジニアが作るプロダクトとは「現場の解像度」が根本から異なる。2025年4月施行の貨物自動車運送事業法改正で義務化された実運送体制管理簿の作成・保管は、まさに今ニーズが最高潮に達している。

**MVP設計案:**
- **最小機能:**
  - 傭車会社マスタ（名前・連絡先・単価）
  - 案件登録（日付・荷主・傭車会社・便名・金額）
  - 月次集計・精算一覧表示
  - 実運送体制管理簿フォーマットへのPDF出力（法定帳票）
  - （次フェーズ）傭車会社への請求書確認用共有リンク
- **技術スタック:** SwiftUI（iOS） + Supabase（認証・DB・無料枠）。PDF生成はPDFKit
- **想定工数:** 2〜3ヶ月（法定帳票のフォーマット調査1〜2週間含む）
- **最初の収益化方法:** 月額3,000〜5,000円のサブスクリプション（StoreKit 2）。最初の10社は知人・業界つながりから直接営業（インサイダーとして既存のコネクションを活用）

**リスク・注意点:**
- 法令要件が変わると帳票フォーマットの更新が必要（メンテナンスコスト）
- 中小運送会社の経営者へのリーチ方法：業界メディア（物流ニュース等）への寄稿・X(Twitter)での露出が必要
- AppLogiやGO運転管理が傭車機能を拡充中。スピードが重要
- 法定帳票を扱うため、法改正への追従義務が発生する（ただし逆に言えば競合も常に追われる）

## 🥈 第2位: ハンドメイド作家向け原価・在庫・売上管理iOSアプリ

**総合スコア: 79/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | CRUD操作＋計算ロジック＋CloudKit同期。Swift初〜中級でも2ヶ月以内にMVP完成可能。UI設計が勝負 |
| 市場規模 | 14/20 | minne登録作家数は約100万人（2024年）。アクティブ販売者は数十万人規模。ただし課金率は低め |
| 競合の少なさ | 19/20 | App Storeで「ハンドメイド 原価」で専用iOSアプリはほぼ0。WebのExcelテンプレートが競合 |
| EigoCheckとの相乗効果 | 12/20 | StoreKit 2（App内課金）・CloudKit・SwiftUIのコードが直接流用できる。ターゲットは異なるがApp Store運用知見は共通 |
| マネタイズ可能性 | 16/20 | 月額480〜980円（個人作家向け）。1,000人有料ユーザーで月48〜98万円。ただし作家の月課金意欲はやや低め。買い切り1,500〜2,000円も選択肢 |

**なぜ今のオーナーに向いているか:**
日本のminne/Creema文化に特化したツールは海外アプリが参入しにくい。計算ロジックはminne手数料9.6%・Creema手数料10%・送料パターン等の日本固有仕様を内蔵すれば、一般的な在庫管理アプリとは根本から差別化できる。EigoCheckで積み上げたiOSアプリ開発・リリース・App Store最適化の経験がほぼそのまま活きる。

**MVP設計案:**
- **最小機能:**
  - 素材マスタ（名前・単価・在庫数）
  - 商品登録（使用素材・工数時間・希望利益率 → 推奨販売価格を自動計算）
  - minne/Creema手数料を選択して手取り額を即時表示
  - 売上記録（どのプラットフォームで何個売れたか）
  - 月次サマリー（売上・原価・利益のダッシュボード）
- **技術スタック:** SwiftUI + CloudKit（オフライン対応）。グラフはSwift Charts
- **想定工数:** 1.5〜2ヶ月
- **最初の収益化方法:** 無料（商品登録5件まで）＋月額480円または買い切り1,480円のアンロック。X(Twitter)でハンドメイド作家コミュニティへの直接アプローチ

**リスク・注意点:**
- minne/Creemaの手数料率改定への追従が必要
- 作家コミュニティへのリーチ：InstagramとX(Twitter)のハンドメイドハッシュタグ（#ハンドメイド原価）での露出が鍵
- 月額課金への心理的ハードルが高いユーザー層（副業・趣味兼業が多い）。買い切りの方が売れる可能性
- Googleスプレッドシートの無料テンプレートとの戦い：UI/UXでの圧倒的な使いやすさが必要

## 🥉 第3位: EigoCheck「音声+添削」統合モード（EigoCheckの機能拡張）

**総合スコア: 74/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | EigoCheckの既存キーボード拡張に Speech Framework を追加。API費用がOpenAI Whisper分増えるが設計は難しくない |
| 市場規模 | 16/20 | Speakが日本で急成長中（2025〜2026年）。英語ライティング＋発音の統合ニーズが実証されている |
| 競合の少なさ | 14/20 | 添削×発音の統合は競合が薄いが、SpeakやDuolingo Maxが機能拡充してくると競合化する可能性 |
| EigoCheckとの相乗効果 | 20/20 | 既存コード・既存ユーザー・既存App Store評価・既存APIインフラを100%活用。投資対効果が最大 |
| マネタイズ可能性 | 9/20 | EigoCheck既存ユーザーへのアップセルが中心。新規市場を開拓するより既存ユーザーの課金率を上げる施策 |

**なぜ今のオーナーに向いているか:**
EigoCheckの既存コードベース・App Store評価・ユーザーベースをそのまま活用できる唯一のアイデア。開発工数が最も短く、既存ユーザーへのアップセルとしてリリース直後から収益が期待できる。Speakが急成長しているという市場検証も追い風。

**MVP設計案:**
- **最小機能:**
  - 添削完了後「この文章を音読してみよう」ボタンを表示
  - Speech Framework でマイク録音 → Whisper API でテキスト化 → 元文章と比較して発音ヒントを表示
  - 「発音分析」機能として既存プレミアムプランに追加（または新プランを作成）
- **技術スタック:** 既存EigoCheckコード + AVFoundation + OpenAI Whisper API
- **想定工数:** 3〜6週間（既存アーキテクチャへの統合が主な作業）
- **最初の収益化方法:** 既存プレミアムプランの値上げ（発音機能追加で+月額200〜500円）またはアドオン課金

**リスク・注意点:**
- API費用（Whisper）が増えるため価格設計に注意
- 発音判定の精度：日本語訛りへの対応が課題（Duolingoが批判されているのと同じ問題）
- 既存ユーザーへの価値追加としては明確だが、新規ユーザー獲得の武器としては弱い可能性
