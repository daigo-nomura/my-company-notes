# アイデア精査レポート — 2026-07-05

## 総評

今回の収集で際立ったのは「義務化・規制ドリブンの需要」と「大手が対応しない小さすぎる市場」の2パターン。前者は運送業界のデジタル化（日報義務化・2024年/2026年問題対応）、後者はフリーランス美容師・個人塾などのニッチBtoB。どちらも確実な需要があるが、マーケティング方法が異なる。EigoCheckの延長線上では「添削ログ蓄積・復習アプリ」が依然として最も実現性が高く、スキルとコードの無駄が最小という点で群を抜く。

## 🥇 第1位: EigoCheck Learning Log（英会話練習ログ記録・復習アプリ）

**総合スコア: 81/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | EigoCheckのGPT-4o API連携コードをほぼそのまま流用可能。SwiftUI + CoreData/CloudKit で保存・同期。AVSpeechSynthesizer で音声読み上げも追加コストほぼゼロ。3ヶ月どころか1.5ヶ月でMVP可能 |
| 市場規模 | 15/20 | 英語学習アプリ市場は巨大だが競合も多い。ただし「添削ログ特化」というニッチに絞れば直接競合は3件以下。EigoCheckユーザーからのクロスセルで初期ユーザー獲得の見通しが立つ |
| 競合の少なさ | 14/20 | 「英語添削キーボード + ログ保存 + 復習」をセットで提供するiOSアプリは現状ほぼ存在しない。Grammarlyは添削のみでログ蓄積なし。GingerもIDIYも復習機能なし |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckの既存ユーザーが最初のユーザーになる。API連携コード・SwiftUIの設計・App Storeの審査実績・開発者ページがそのまま活用できる。EigoCheck有料版とのバンドル化も可能 |
| マネタイズ可能性 | 14/20 | 月額480〜980円のフリーミアムが現実的。EigoCheckユーザー100人が有料転換するだけで月5〜10万円に到達。6ヶ月以内の達成は業界平均より有利なスタート地点から始められる |

**なぜ今のオーナーに向いているか:**
Swift中〜初級でも、既存のEigoCheckコードがあるため「ゼロから設計する必要がない」。最大のリスクであるユーザー獲得も、EigoCheckの既存ユーザーがいるため初期0人問題が発生しない。日本語ユーザー向けという得意領域をそのまま活かせる。

**MVP設計案:**

- **最小機能:**
  1. EigoCheckで添削した英文と修正案を自動保存（or 手動コピペで保存）
  2. 保存した添削ペア（原文・修正文・修正理由）のリスト表示
  3. フラッシュカードモードで1枚ずつ復習
  4. AVSpeechSynthesizerで修正文を音声読み上げ

- **技術スタック:** SwiftUI + CoreData（ローカル）+ CloudKit（iCloud同期）+ OpenAI API（修正理由の自動生成）+ AVSpeechSynthesizer

- **想定工数:** 6〜8週間（EigoCheckコードの流用前提）
  - Week 1-2: データモデル設計・CoreData実装・EigoCheckとのデータ連携
  - Week 3-4: リスト画面・フラッシュカードUI
  - Week 5-6: CloudKit同期・音声読み上げ・App Store申請準備
  - Week 7-8: ベータテスト・審査・リリース

- **最初の収益化方法:**
  - 無料: 添削ログ50件まで保存・復習
  - 月額480円（年額3,800円）: 無制限保存 + フラッシュカード + 音声読み上げ
  - EigoCheck有料ユーザー向けに30日間無料トライアル付きのクロスセル告知

**リスク・注意点:**

- 英語学習アプリ全体の競合は激しい。「EigoCheckの姉妹アプリ」という文脈を前面に出さないとApp Storeで埋もれるリスクあり
- EigoCheckがあまり使われていなければクロスセル効果が低い。まずEigoCheckのアクティブユーザー数を確認すること
- Duolingo・スピークバディ等の大手が「ログ蓄積」機能を追加すれば差別化が消える。開発スピードが命

## 🥈 第2位: フリーランス美容師向けシンプル予約＋カルテiOSアプリ

**総合スコア: 71/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + CloudKit でカルテ（顧客情報・施術記録・写真）と予約カレンダーを実装。Calendarフレームワークとの統合がやや複雑だが3ヶ月以内は現実的。LINEとのURL連携で予約通知も可能 |
| 市場規模 | 16/20 | 日本のフリーランス美容師は数万人規模。一人サロン・業務委託美容師が増加中。Instagram・TikTok利用率が高くSNSマーケが自然に刺さる |
| 競合の少なさ | 15/20 | 月額3,000〜5,000円のiOSネイティブアプリで個人向けに最適化されたものは少ない。Salonboardなど既存は多機能・高額でフリーランスには過剰 |
| EigoCheckとの相乗効果 | 7/20 | ユーザー層は完全に異なる。ただしSwiftUI・CloudKit・App Store申請ノウハウが転用できる。同一Appleデベロッパーアカウントで展開できる |
| マネタイズ可能性 | 16/20 | 月額3,000〜4,800円設定で、10人の有料ユーザーで月3〜5万円に到達。美容師はInstagramで繋がりやすくユーザー獲得コストが低い。業務ツールなのでチャーン率が低い |

**なぜ今のオーナーに向いているか:**
EigoCheckで培ったSwiftUI + CloudKitのパターンが完全流用可能。「日本のフリーランス美容師」という具体的なターゲット像が明確でマーケ戦略が立てやすい。Instagramのみで初期ユーザーを獲得でき、広告費ゼロで始められる。

**MVP設計案:**

- **最小機能:**
  1. 顧客カルテ（名前・連絡先・施術履歴・メモ・写真1〜3枚）
  2. 予約スケジュール管理（カレンダービュー）
  3. LINEボタンで予約確認メッセージ送信
  4. 月次売上サマリー（何人×いくら）

- **技術スタック:** SwiftUI + CloudKit + EventKit（カレンダー連携）+ PhotosUI

- **想定工数:** 10〜12週間
  - Week 1-3: データモデル・カルテCRUD
  - Week 4-6: カレンダーUI・予約管理
  - Week 7-9: 写真添付・月次集計・LINE連携
  - Week 10-12: テスト・App Store申請・β版ユーザー10人獲得

- **最初の収益化方法:**
  - 無料: 顧客10人まで
  - 月額3,800円: 無制限 + 売上集計 + iCloud同期
  - Instagramでフリーランス美容師アカウントにDMでβテスター募集

**リスク・注意点:**

- EigoCheckとのユーザー重複ゼロなので、新規マーケティングを一から構築する必要がある
- カレンダーUIは実装量が多い。EventKitの制約（iOSカレンダーとの統合）で想定外のバグが出やすい
- フリーランス美容師市場には既に「MINIMO」「meetus」「Airリザーブ」等が存在。無料で使えるツールとの比較で価格正当化が必要

## 🥉 第3位: 傭車管理台帳アプリ（中小運送会社向け）

**総合スコア: 67/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | 傭車の発注記録・支払管理・月末集計というシンプルなCRUDアプリ。SwiftUI + CloudKit or Firebase。3ヶ月以内MVP可能。ただし業界特有の帳票出力（PDF請求書）の実装が少し複雑 |
| 市場規模 | 12/20 | 日本の運送会社（10〜50台規模）は数万社存在するが、個人開発者が営業なしでBtoBにリーチするのは難しい。会社の業界ネットワークを使えるなら高得点だが、そこに頼ると本業との利益相反リスクあり |
| 競合の少なさ | 19/20 | App Storeで傭車管理に特化したアプリはほぼ存在しない。大手ERPの一機能としてのみ存在。この空白は本物 |
| EigoCheckとの相乗効果 | 5/20 | ユーザー層・課題・マーケティングチャネルが完全に異なる。SwiftUIスキルは流用できるが、それ以外の資産は活用困難 |
| マネタイズ可能性 | 15/20 | 月額5,000〜10,000円/社のBtoB価格設定が可能。IT導入補助金を活用した販売で顧客の実質負担を下げられる。6ヶ月以内10社獲得（月5〜10万円）は業界人脈があれば現実的 |

**なぜ今のオーナーに向いているか:**
業界インサイダーとして「何が本当に困っているか」を知っている唯一の個人開発者。傭車管理の複雑さ（会社ごとに単価・条件が違う、月末の精算が煩雑）を設計に反映できる。競合がほぼゼロで、App Storeに出すだけで見つけてもらえる可能性がある。

**MVP設計案:**

- **最小機能:**
  1. 傭車会社マスタ（会社名・担当者・単価設定）
  2. 案件ごとの傭車発注記録（日付・ルート・台数・費用）
  3. 月末集計（会社別・期間別の傭車費用サマリー）
  4. PDF出力（支払確認書 / 月次集計レポート）

- **技術スタック:** SwiftUI + CloudKit + PDFKit（PDF出力）

- **想定工数:** 8〜10週間

- **最初の収益化方法:**
  - 月額4,800〜9,800円/社
  - 勤務先の業界ネットワーク外（競合他社・取引先）への直接営業は避け、SNS（X/Twitter）・物流業界メディアへの寄稿で認知獲得
  - IT導入補助金対応として申請サポートをリード獲得のフックにする

**リスク・注意点:**

- 本業（デジタコ・運行管理システムメーカー）との利益相反に注意。会社の顧客に個人で営業するのは就業規則上NGの可能性が高い。販売チャネルは本業外ルートに限定すること
- 法人向け販売は契約・インボイス対応・サポートの工数が個人にとって思ったより重い
- 点呼記録・IT点呼など法令準拠が必要な機能には手を出さない。「社内記録補助ツール」に機能を限定することで規制リスクを回避
