## 🥇 第1位: EigoCheckビジネスメール特化モード（キーボード型英語添削の拡張）

**総合スコア: 84/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 19/20 | 既存のiOS Custom Keyboard Extensionにプリセット（件名・冒頭・結び・ビジネス表現候補）を追加する形で実装。既存API呼び出しロジックを流用。2〜4週間でMVP、3ヶ月以内に完成形 |
| 市場規模 | 15/20 | 「ビジネスメール英語」はEigoCheckユーザーの中でも最需要ニーズ。外資転職・グローバル企業勤務・海外取引ユーザー層は課金意欲が高い。競合がキーボード型をやっていないため差別化が効く |
| 競合の少なさ | 15/20 | UGUIS.AI・Eigoduke・iDiy等がアプリ内学習型で添削市場に参入。ただし「キーボード型×ビジネスシーン特化」は2026年7月時点でほぼ空白。UGUIS.AIはApp Storeに存在するが別アプリ型 |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckの直接的な機能拡張。既存コード・APIロジック・UIコンポーネント・ユーザーベース・App Storeレビュー・マーケティングチャネルをすべて流用。追加開発コストが最小 |
| マネタイズ可能性 | 15/20 | 「ビジネスメールモード」をプレミアム機能（月額480〜980円 or 年額3,980円）として設定し既存ユーザーにアップセル。EigoCheckが100ユーザーいれば10〜20%の転換で月5,000〜20,000円。リリース後3ヶ月で月3万円突破が現実的ターゲット |

**なぜ今のオーナーに向いているか:**
- 既存コードを活用するため「初めてゼロから作る」リスクがない
- EigoCheckのユーザーが「次に欲しい機能」として自然な横展開
- ビジネスメール英語の需要は法人ユーザー獲得への橋頭堡にもなる
- 競合はアプリ内学習型に集中しており、キーボード型の空白を守る戦略として最優先

**MVP設計案:**
- 最小機能: ①ビジネスメール専用プリセット（件名・冒頭挨拶・本文・締め）②文体トーン切替（フォーマル/カジュアル）③「そのまま使えるフレーズ提案」（添削だけでなく表現候補を3択で提示）
- 技術スタック: Swift / SwiftUI（既存EigoCheckコードベース）+ Anthropic Claude API（既存API呼び出し）+ プレミアム課金（StoreKit 2）
- 想定工数: 設計1週間 + 実装2〜3週間 + テスト1週間 = 計4〜5週間（1ヶ月以内にMVP可能）
- 最初の収益化方法: EigoCheckアプリ内のIn-App Purchase（月額・年額プラン）として提供。既存無料ユーザーへのプッシュ通知で告知

**リスク・注意点:**
- EigoCheckが現時点でユーザー数が少ない場合、アップセル母数が小さく月3万円達成が遅れる可能性。その場合は新規ユーザー獲得と並行して進める必要あり
- ビジネスメール特化にすると学習用途のユーザーとターゲットが分離する。UI設計で「学習モード/実務モード」の切り替えを明確にすること

## 🥈 第2位: ネイリスト専用カルテ管理iOSアプリ

**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | 写真撮影+テキスト入力+顧客リスト+CloudKit同期という構成。SwiftUI + PhotosKit + CloudKit or Supabaseで完結。複雑なアーキテクチャ不要。2〜2.5ヶ月でMVP可能 |
| 市場規模 | 15/20 | 日本のネイリスト人口は約4〜5万人。フリーランス化・個人ネイリスト増加中。月3,000〜5,000円の価格帯で1,000人ユーザーで月300〜500万円の理論値。現実的な初期目標は100人＝月30〜50万円 |
| 競合の少なさ | 17/20 | minimo・nailieは「集客プラットフォーム」。カルテ管理（写真+施術記録+顧客履歴）に特化したiOSアプリは検索しても見当たらない。ほぼ空白地帯 |
| EigoCheckとの相乗効果 | 6/20 | ユーザー層・コードとも別物。SwiftUI設計・StoreKit課金実装のスキルは流用できる |
| マネタイズ可能性 | 15/20 | フリーミアム（顧客10名まで無料、以降月3,000〜4,800円）が王道設計。月50人の有料ユーザーで月15〜24万円。6ヶ月以内に達成可能な現実的プラン |

**なぜ今のオーナーに向いているか:**
- iOSネイティブ機能（カメラ・写真管理・ウィジェット）を活用できる題材で、SwiftUIの強みが最大化できる
- ユーザーが「紙とスマホ写真でやっている」ため、移行コストが低い（高機能システムへの移行より敷居が低い）
- ニッチに絞ることで初期ユーザーへのリーチがTwitter・美容師系インフルエンサーへのDMで代替可能

**MVP設計案:**
- 最小機能: ①顧客登録（名前・連絡先・アレルギー）②施術記録（日付・メニュー・写真・メモ）③顧客ごとの施術履歴一覧④次回予約リマインダー
- 技術スタック: SwiftUI + PhotosKit + CloudKit（iCloud同期）+ StoreKit 2（課金）
- 想定工数: 設計2週間 + 実装6〜7週間 + テスト・UI改善2週間 = 計10〜11週間（2.5ヶ月）
- 最初の収益化方法: 無料プラン（顧客10名まで）+ プレミアム月額3,800円。Twitterのネイリストコミュニティ・#ネイリスト等のハッシュタグ経由でオーガニック告知

**リスク・注意点:**
- ネイリスト業界はITリテラシーがバラつく。UIが複雑だと「スマホで十分」と判断される。徹底したシンプル設計が必須
- 初期のユーザー獲得がBtoCのためSNS告知が必要。オーナーが業界コネクションを持たない場合、認知獲得に時間がかかる可能性

| 競合の少なさ | 19/20 | iOS App Storeに「傭車管理専用」アプリはほぼ皆無。大手TMSは高額・機能過多。中小向け軽量ツールは完全空白。業界インサイダー視点でも「誰も作っていない」と確信できる領域 |
| EigoCheckとの相乗効果 | 5/20 | ユーザー層・コードとも別物。SwiftUI/Supabase経験が流用できる程度 |
| マネタイズ可能性 | 16/20 | BtoBのため単価が高い。月8,000円×30社=月24万円が6ヶ月以内のターゲット。2026年物流法改正による「書面化義務」でニーズが急増しており、需要の波に乗りやすい。勤務先のネットワークで初期顧客2〜3社の確保が現実的 |

**なぜ今のオーナーに向いているか:**
- デジタコ・運行管理システムメーカー勤務という業界インサイダー優位が他の個人開発者に真似できない最大の差別化要因
- 勤務先の顧客ネットワーク（中小運送会社）にテスト導入を依頼できる可能性がある
- 2026年4月の物流法改正（傭車の書面化義務）で「今すぐ対応しなければならない」層が増え、タイミングが良い

**MVP設計案:**
- 最小機能: ①傭車依頼登録（日時・便名・傭車会社・運賃）②傭車会社マスタ管理③月次精算書PDF出力④傭車別・月別集計レポート
- 技術スタック: SwiftUI（iOSアプリ）+ Supabase（マルチユーザー対応クラウドDB）+ PDFKit（PDF出力）+ StoreKit 2（月額課金）
- 想定工数: 設計2週間 + 実装7〜8週間 + テスト・現場フィードバック反映3週間 = 計12週間（3ヶ月ぴったり）
- 最初の収益化方法: 初期3社に無料で使ってもらいフィードバック収集→月額8,000円/社の有料化。勤務先の人脈経由で営業。ITコーディネーター・商工会議所経由での展開も有効

**リスク・注意点:**
- BtoBのため初期顧客獲得が最大のボトルネック。1〜2社のテスト導入先を先に確保してからMVP開発に着手することを強く推奨
- 運送業は紙文化が強く「スマホで入力する」習慣定着に時間がかかる場合がある。現場ドライバーではなく「配車担当事務員」が入力するツールとして設計すると普及しやすい
- 勤務先との利益相反（業務として行うシステム開発と副業・個人開発が重複しないか）の確認が必要
