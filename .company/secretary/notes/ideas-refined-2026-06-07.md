## 🥇 第1位: ドライバー日報デジタル化アプリ

**総合スコア: 75/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUI + Core Data + PDFKit のみ。フォーム設計（出発時刻・走行距離・積荷メモ・アルコールチェック数値・写真）は複雑ではない。PDF出力はPDFKitで対応可。3ヶ月MVP確実 |
| 市場規模 | 15/20 | 中小運送会社（10〜50台）は国内数万社規模。ただしBtoBのため顧客獲得は対面・紹介が主で時間がかかる。絶対数は大きい |
| 競合の少なさ | 18/20 | App Storeで「日本語・シンプル・運送業特化・月額3,000円以下」を満たすアプリはほぼ存在しない。既存競合（AppLogi等）は高機能・高価格帯 |
| EigoCheckとの相乗効果 | 5/20 | ユーザー層・コード・技術ともにほぼ共通点なし。完全に別プロダクトとして立ち上げが必要 |
| マネタイズ可能性 | 19/20 | 月額3,000〜5,000円×30社で月9〜15万円。業界インサイダーとして直販（業界展示会・同業者への紹介）が可能。6ヶ月で3万円/月は十分現実的 |

**なぜ今のオーナーに向いているか:**
デジタコ・運行管理システムメーカー勤務という業界インサイダーとしての知識は、他の個人開発者が絶対に持てない最大の武器。「現場で本当に使えるUI」「ドライバーが入力したくなるシンプルさ」「配車担当が集計しやすいPDF形式」を設計できるのはオーナーだけ。競合大手システムが10〜30万円/月の価格帯であるのに対し、3,000〜5,000円/月というシンプル特化の価格設定で中小事業者の隙間を狙える。

**MVP設計案:**
- **最小機能:**
  1. ドライバー情報の登録（名前・車両番号）
  2. 日報入力フォーム（出発時刻・帰着時刻・走行距離・アルコールチェック数値・体調確認・一言メモ）
  3. 写真添付（アルコール検知器の数値写真）
  4. 日報一覧・過去の検索
  5. PDF書き出し（月次まとめ）→ メール共有

- **技術スタック:**
  - SwiftUI（UI全体）
  - Core Data（ローカル保存）
  - PDFKit（PDF生成）
  - PhotosUI（写真キャプチャ）
  - バックエンドなし（v1はオフライン完結でOK）

- **想定工数:**
  - Week 1〜2: データモデル設計 + Core Data セットアップ + 入力フォームUI
  - Week 3〜4: 日報一覧・検索・詳細表示
  - Week 5〜6: PDF生成・共有
  - Week 7〜8: テスト・磨き込み・App Store申請
  - → **2ヶ月でMVP可能**（3ヶ月の余裕あり）

- **最初の収益化方法:**
  - フリーミアム：3人まで無料 → 4人以上は月額3,000円
  - または: 14日間無料トライアル → 月額3,000円
  - 業界の知人・同業者への直販（展示会・業界SNSでの口コミ）

**リスク・注意点:**
- BtoBの顧客獲得は個人では時間がかかる。最初の10社を獲得するまでが最難関
- 配車担当・経営者との打ち合わせが必要で、サポート負荷がBtoCより高い
- 競合大手が「シンプル版」を安価にリリースしたら即座に競合化するリスク
- 法改正（点呼記録要件の変更等）への対応が必要になる可能性

## 🥈 第2位: 英語日記 + AI添削 iOSアプリ

**総合スコア: 72/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | EigoCheckのキーボード拡張開発で得たSwiftUI・OpenAI API呼び出しの知識がそのまま流用可能。日記入力UI + OpenAI API + ローカル保存のみ。独立アプリとして3ヶ月MVP確実 |
| 市場規模 | 16/20 | 日本の英語学習者は潜在的に数千万人規模。ただしBtoCは獲得単価が高く、月額課金の継続率をどう維持するかが課題 |
| 競合の少なさ | 11/20 | 英語学習アプリ市場は激戦区。Grammarlyが上位に君臨。ただし「日本語で詳しく解説する英文添削日記」という切り口では直接競合が少ない |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckユーザーへのアップセル・クロスセルが可能。技術スタックが完全共通（SwiftUI + OpenAI API）。開発スピードが大幅に向上する |
| マネタイズ可能性 | 8/20 | 月額500〜980円×300人で15〜30万円。ただし300人の有料ユーザー獲得まで数ヶ月〜1年かかる見込み。EigoCheckのユーザーベースがあれば加速できる |

**なぜ今のオーナーに向いているか:**
EigoCheckの開発経験がそのまま活かせるため、技術リスクがほぼゼロ。EigoCheckのユーザー（英語を書くことに慣れたい日本人）は、英語日記アプリの最大のターゲット層と完全一致する。英語添削市場でGrammarlyに勝てる唯一の差別化は「日本語で丁寧に解説する」こと。EigoCheckで培ったこの強みをそのまま独立アプリとして展開できる。

**MVP設計案:**
- **最小機能:**
  1. 日記入力画面（英文テキスト入力）
  2. AI添削ボタン → OpenAI APIで英文チェック + 日本語で理由を解説
  3. 過去の日記一覧（カレンダービュー）
  4. 連続学習日数カウンター（継続のモチベーション維持）
  5. シェア機能（添削結果をX/LINEに共有）

- **技術スタック:**
  - SwiftUI
  - OpenAI API（GPT-4o または GPT-4.1 mini）
  - Core Data（ローカル日記保存）
  - StoreKit（サブスクリプション課金）

- **想定工数:**
  - EigoCheckの知識流用で → **1.5〜2ヶ月でMVP可能**

- **最初の収益化方法:**
  - 月10日分まで無料 → 月額980円でアンリミテッド
  - EigoCheckユーザーへの案内（アプリ内クロスプロモーション）

**リスク・注意点:**
- 英語学習アプリ市場は競合が多く、App Store上での発見されにくさが最大のリスク
- OpenAI APIコストは1ユーザーあたり月数十円程度。スケールすると利益率に影響
- EigoCheckが伸びていないとクロスセルの効果が限定的になる

## 🥉 第3位: 整体師・鍼灸師向け電子カルテ iOSアプリ

**総合スコア: 68/20**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUI + Core Data のみのシンプルCRUD。患者一覧・施術記録フォーム・次回予約メモ。バックエンド不要でMVP可能。3ヶ月で確実に完成できる |
| 市場規模 | 13/20 | 日本の鍼灸師約12万人・整体師10万人超。ただし全員がiOSアプリを使うわけではなく、浸透させるまでに時間がかかる |
| 競合の少なさ | 17/20 | 美容師・エステ向けカルテアプリ（KaruteKun等）は多いが、整体・鍼灸に特化したiOSアプリはほぼ2〜3件のみ。いずれもUI/UXが古く評価が低い |
| EigoCheckとの相乗効果 | 3/20 | ユーザー層・技術ともに共通点なし |
| マネタイズ可能性 | 17/20 | 月額2,000〜4,000円×50院で10〜20万円が目標。KaruteKunが月額2,980円で2,600店舗導入できている事実からBtoB課金意欲は高い |

**なぜ今のオーナーに向いているか:**
実装が最もシンプルで「動くMVP優先」というオーナーのスタイルに合う。競合が少なく、既存アプリへの不満（UIが古い・機能過多）を「シンプルで今すぐ使える」で解決すれば差別化できる。ただし整体・鍼灸業界のドメイン知識がないため、最初の3〜5名のユーザーインタビューが必須。

**MVP設計案:**
- **最小機能:**
  1. 患者登録（名前・連絡先・主訴）
  2. 施術記録（日付・施術部位・施術内容・次回方針）
  3. 患者一覧・検索
  4. カルテ詳細（施術歴の時系列表示）

- **技術スタック:**
  - SwiftUI + Core Data
  - オプション: CloudKit（複数端末同期、v2で追加）

- **想定工数:** 2ヶ月でMVP可能

- **最初の収益化方法:**
  - 5患者まで無料 → 月額2,980円でアンリミテッド
  - 整体師コミュニティ（Twitter・Facebook グループ）への直接アプローチ

**リスク・注意点:**
- 整体・鍼灸業界のドメイン知識がないため、「実際の現場で使えるUI」を設計するためにユーザーインタビューが必須
- 医療・個人情報の取り扱いが含まれるため、プライバシーポリシー・利用規約の整備が必要（これ自体はライセンス不要だが手間）
- 顧客獲得チャネルが「整体師コミュニティ」に限定されるため、最初の10院獲得に時間がかかる
