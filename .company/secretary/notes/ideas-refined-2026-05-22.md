**総合スコア: 76/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | SwiftUI + Claude/GPT API の組み合わせ。EigoCheckと同じAPIスタック。キーボードエクステンション不要でむしろ簡単。日課ループUIはDuolingo的なStreakで実装例多数 |
| 市場規模 | 16/20 | 英語学習者は日本で3,000万人超。「英語日記を書きたいが続かない」「添削してほしい」需要は長年ある。EigoCheckユーザーへのクロスセルで初期DAU確保可能 |
| 競合の少なさ | 12/20 | HelloTalk・lang-journal系の英語日記添削アプリが5件程度存在する。ただし「毎日のプロンプト提示＋AI添削＋弱点記憶カード」のセットを持つアプリはほぼない |
| EigoCheckとの相乗効果 | 18/20 | ユーザー層が完全に同じ（英語が不安な日本人）。AI添削コードは流用可能。App Storeページからの導線設置・EigoCheckのレビュー欄でも告知可能。開発スキルの再利用率が最高 |
| マネタイズ可能性 | 15/20 | 月額380〜680円のフリーミアム（無料: 1日3文まで、有料: 無制限+弱点カード）。EigoCheckの既存ユーザーへのクロスセルがあれば6ヶ月以内に月3〜5万円は現実的 |

**なぜ今のオーナーに向いているか:**
EigoCheckで培ったiOS Custom Keyboard / AI添削 / App Store審査通過の知見がすべて活かせる。ユーザー獲得はゼロから始める必要がなく、EigoCheckユーザーへのアプリ内告知とApp Storeの「このアプリをお使いの方へ」機能で初期ユーザーを確保できる。Duolingoのような習慣化UIは実装パターンが豊富でSwiftUI初〜中級者でも3ヶ月以内に完成可能。Apple Intelligence（文法チェック機能）との差別化も「日本人が英語で書く時の特有の誤り＋日本語での解説」で明確に取れる。

**MVP設計案:**
- **最小機能**: ①毎日1つの「今日のお題」（例：「最近うれしかったことを3文で書いてください」）を提示 → ②ユーザーが英語で入力 → ③AIが添削・自然な表現を提案・日本語で理由を解説 → ④弱点単語/表現をカード化して翌日出題
- **技術スタック**: SwiftUI + Claude 3.5 Sonnet API（ストリーミング）+ UserDefaults or CloudKit（ローカル保存でもMVPは成立）+ StoreKit 2（サブスク）
- **想定工数**: 4〜6週間でMVP（EigoCheckコードの流用あり）。2〜3ヶ月で機能追加版
- **最初の収益化方法**: 月額480円のProプラン（無料3文/日制限）。EigoCheckのApp Storeページ説明欄に追記→初月50DL目標

**リスク・注意点:**
- Apple Intelligence（Writing Tools）が無料で文法チェックを提供しており、「添削だけ」では差別化が難しい。**「日課ループ＋弱点記録」という習慣化設計**で上回ること
- lang-journal.com等のWebアプリが先行しているため、「iOSネイティブアプリの体験の良さ」と「ウィジェット・通知機能」で優位性を出すこと
- 市場は大きいが飽和気味のカテゴリ。EigoCheckとのシナジーがないと埋没するリスクあり

## 🥈 第2位: 傭車精算管理 シンプルiOSアプリ（仮称：ヨウシャ帳）

**総合スコア: 68/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 14/20 | SwiftUI CRUD + PDF生成（PDFKit）+ CSV出力。技術的には難しくないが、BtoB顧客へのデモ・営業活動がソフトウェア開発と並行して必要。iOSアプリとして完結するMVPは3ヶ月で可能 |
| 市場規模 | 15/20 | 全国の中小運送会社（10〜50台規模）は数万社。傭車を使っている会社は多数。ただし日本全体でのリーチは業界人脈が鍵で、ソロでマーケティングするには限界がある |
| 競合の少なさ | 20/20 | 「傭車精算管理だけ」の単機能アプリはApp StoreでほぼZERO。大手システムは複合機能で高コスト。完全な空白地帯 |
| EigoCheckとの相乗効果 | 2/20 | ユーザー層・スキル・コードの流用は一切ない。完全なピボット。EigoCheckを捨てる覚悟が必要 |
| マネタイズ可能性 | 17/20 | 月額3,000〜5,000円×20社=月6〜10万円。業界人脈で初期5社は知人紹介から始められる。解約率が低い（BtoBの特性）。6ヶ月以内に月3万円達成は現実的 |

**なぜ今のオーナーに向いているか:**
デジタコ×運行管理システムの会社に勤務しており、運送業の業務フロー・傭車精算の具体的な手順・既存システムの限界を第一線で知っている。これは世界で唯一オーナーだけが持つ優位性。競合がゼロに近い理由は「業界を知らない開発者が作れない」から。業界インサイダーが直接顧客の声を聞きながら作るプロダクトはピボットコストが最小。

**MVP設計案:**
- **最小機能**: ①傭車会社マスター登録 → ②案件ごとに「日付・車両・ルート・傭車会社・金額」を入力 → ③月次の傭車費用一覧をPDF出力（請求書照合用）→ ④月末の請求突合を傭車会社別にCSV出力
- **技術スタック**: SwiftUI + CoreData or SwiftData + PDFKit（PDF生成）+ ShareSheet（PDF共有）。バックエンド不要でMVPは完全オフライン動作
- **想定工数**: 6〜8週間でMVP（CoreDataのCRUD + PDF生成が主な実装）。シンプルなUIなので3ヶ月以内に余裕で完成
- **最初の収益化方法**: 14日間無料トライアル → 月額3,000円（会社単位）。初期は知人の運送会社5社に無料提供→フィードバック収集→改善→有料化

**リスク・注意点:**
- **EigoCheckとの相乗効果がない**。2つのアプリを並行開発すると両方中途半端になるリスク。EigoCheckのリリース前後の時期によって判断が変わる
- BtoB営業スキルが必要。「作ったのに誰も使わない」リスクを防ぐため、先に5社からヒアリング→プロトタイプ確認→フィードバックのサイクルを回してから作ること
- 業界規制の変化（点呼義務化の強化等）に追従するメンテナンスコストが継続する
- 勤務先企業との競合になる可能性に注意。副業規定の確認が必須

## 🥉 第3位: ハンドメイド作家向け 原価・在庫・注文管理iOSアプリ（仮称：テテオリ / 原価帳）

**総合スコア: 65/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + iCloud同期（CloudKit）のシンプルCRUD。写真添付、材料費入力、利益率自動計算がコア機能。SwiftUI初〜中級者でも3ヶ月以内に完成できる難易度 |
| 市場規模 | 14/20 | minne登録作家数100万人超・Creemaも数十万人。ただし「アプリにお金を払う」層は全体の数%。月額500〜1,000円帯での有効市場は数万人程度 |
| 競合の少なさ | 17/20 | 「ハンドメイド作家向け原価計算」特化のiOSアプリは3件以下。汎用会計アプリ（freee等）はあるが職種特化ではない |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層が異なる。コードも流用できない。ただし「個人向けiOSアプリ開発・App Storeマーケティング」のノウハウは共有できる |
| マネタイズ可能性 | 14/20 | 月額480〜980円のフリーミアム。minne/Creemaコミュニティへの投稿でバイラル集客可能。6ヶ月で月3万円は達成可能だが上限が見えにくい |

**なぜ今のオーナーに向いているか:**
EigoCheckと同じ「個人ユーザー向けiOSアプリ」のスキルセットで作れる。BtoB営業不要でApp Storeのみで完結。minne/Creemaのコミュニティ（X・note）でターゲットユーザーが集まっており、告知コストが低い。技術的にも最もシンプルで、リリースまでのリスクが低い。

**MVP設計案:**
- **最小機能**: ①材料マスター（品名・単価・単位）登録 → ②作品ごとに使用材料と数量を入力→原価自動計算 → ③minne/Creema販売価格を入力→利益率・粗利を自動表示 → ④在庫数の増減記録
- **技術スタック**: SwiftUI + SwiftData（iOS 17以降）+ CloudKit同期 + CSV書き出し（共有シート）。バックエンド不要
- **想定工数**: 4〜6週間でMVP。写真添付や在庫グラフ等は後回しにしてシンプル版から
- **最初の収益化方法**: 無料（作品5件まで）→ Pro月額480円（無制限）。「minne×ハンドメイド作家」コミュニティにXで投稿して認知獲得

**リスク・注意点:**
- 類似の無料Excelテンプレートが無料で出回っており「なぜお金を払うか」の説得が必要
- ハンドメイド市場はLINEやInstagramでのコミュニティが主流。App Storeだけのマーケティングでは届きにくい層がいる
- EigoCheckとの相乗効果がほぼゼロのため、「2本目の柱」として立てるのは良いが、EigoCheckのリリースと収益化を先に完了させてから着手する方が分散リスクを防げる
