## 🥇 第1位: 傭車管理シンプルアプリ（中小運送会社向け）

**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | SwiftUI + CoreData + iCloud同期で配車担当者・経営者がiPad/iPhoneで使えるシンプルCRUDアプリ。3ヶ月で確実にMVP可能。データモデルは「便 × 傭車先 × 運賃 × 状態」の4軸のみでシンプル |
| 市場規模 | 16/20 | 全国の中小運送会社（10〜50台規模）は数万社規模。2026年4月施行の貨物自動車運送事業法改正で「実運送体制管理簿」の作成・保存が義務化 → 強制ニーズ発生 |
| 競合の少なさ | 17/20 | 傭車管理専用のシンプルiOSアプリはほぼ存在しない。AppLogiは中〜大規模向け総合プラットフォーム（高額）。K-LINKは軽貨物専用で一般運送には不向き |
| EigoCheckとの相乗効果 | 5/20 | 英語学習との接点なし。SwiftUIの実装スキルのみ流用可能。既存ユーザーベースの横展開は不可 |
| マネタイズ可能性 | 17/20 | 月額3,000〜5,000円/社が適正価格帯（K-LINKの1,000円/ドライバー×3〜5名分の感覚）。10社獲得で月3〜5万円。勤務先人脈でベータ顧客3〜5社を確保すれば6ヶ月以内の収益化が現実的 |

**なぜ今のオーナーに向いているか:**
デジタコ・運行管理システムメーカー勤務という立場は、他の個人開発者が絶対に持てない資産。傭車管理の「何が本当に面倒か」を知っている。顧客候補の運送会社への直接アクセスも持っている可能性が高く、初期顧客獲得のコールドスタート問題を回避できる唯一のアイデア。

**MVP設計案:**
- **最小機能**: 傭車依頼登録（便名・日付・傭車先・運賃・荷主）→ 月次一覧CSV出力のみ
- **技術スタック**: SwiftUI + CoreData + iCloud Backup（同期）。サーバーレスで初期コストゼロ
- **想定工数**: データモデル設計2週間 → UI実装4週間 → テスト・修正2週間 = 合計8週間（2ヶ月）で余裕あり
- **最初の収益化方法**: 買い切り4,800円（Appストア）または月額980円サブスク。まず勤務先人脈3〜5社にTestFlight無料提供→フィードバック収集→有料化

**リスク・注意点:**
- 勤務先との利益相反が発生しないか確認が必要（副業・競業避止義務の確認）
- BtoB営業が最低限必要（ただし業界人脈で代替可能）
- 2026年4月法改正の「実運送体制管理簿」の要件を正確に把握してアプリに反映しなければ価値が下がる

## 🥈 第2位: ハンドメイド作家向け原価計算＆在庫管理アプリ（iOS）

**総合スコア: 68/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + CoreData（材料マスタ → 商品レシピ → 在庫計算 → 利益計算）。UIはシンプルなフォームとリスト。minne手数料10.56%の自動計算も追加しやすい。3ヶ月以内に確実に完成できる難易度 |
| 市場規模 | 14/20 | minne/Creema合計で数十万人の出品者が存在。ただしBtoCで単価が低いため、ダウンロード数が必要。月3〜10万円達成にはある程度のDL数が必要 |
| 競合の少なさ | 18/20 | ハンドメイド作家向け原価計算＋在庫管理の統合iOSアプリが実質ゼロ。自作Excelをnoteで配布する記事が上位表示されるほど専用ツールが存在しない |
| EigoCheckとの相乗効果 | 6/20 | 英語学習との接点はほぼなし。SwiftUI実装スキルの流用のみ。ただし「個人向けiOSアプリの開発・運用ノウハウ」という意味では同じ |
| マネタイズ可能性 | 14/20 | 買い切り1,480円が現実的な価格帯。月100DLで月約14万円（App Store手数料30%控除後）。ただしDL数の獲得が不確実。月額480円サブスクならより安定するが転換率が課題 |

**なぜ今のオーナーに向いているか:**
「作れる条件」を最も素直に満たすアイデア。複雑なアーキテクチャが不要で、データモデルが明確（材料→商品→在庫→売上の4テーブル）。競合ゼロという状況は今のうちに動ければファーストムーバーになれる。EigoCheckと並行開発しやすい規模感。

**MVP設計案:**
- **最小機能**: 材料マスタ登録（名称・単価・単位）→ 商品レシピ登録（材料×数量）→ 原価自動計算 → minne/Creema手数料込み利益シミュレーション
- **技術スタック**: SwiftUI + CoreData。後からiCloud同期追加可能
- **想定工数**: データモデル1週間 → UI（材料・商品・計算画面）5週間 → テスト2週間 = 8週間
- **最初の収益化方法**: App Store買い切り1,480円。ハンドメイドYouTuber・minneブログ経由でのオーガニック流入を狙う

**リスク・注意点:**
- ターゲット層（ハンドメイド作家）はApp Storeへの習熟度にばらつきがある
- minne/Creemaの手数料体系が変わったらアプリ内の計算式を更新する必要がある
- BtoC単価が低いため、月10万円達成には月100DL程度が必要 → ASO（App Store最適化）が重要

## 🥉 第3位: ペット海外渡航チェックリスト＆タイムライン管理ツール

**総合スコア: 65/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | 最もシンプル。渡航予定日入力 → 国選択 → タイムライン自動生成。Webツール（HTML/JS）でもiOSアプリでも実装可能。データは静的JSONで管理できる |
| 市場規模 | 12/20 | 海外赴任・移住でペットを連れていく層は日本全体では限定的。年間数万件規模と推定されるが、月3〜10万円達成には有料転換が必須 |
| 競合の少なさ | 16/20 | DIYで手続きを進めるためのステップ別ガイド＋チェックリストアプリは完全な空白地帯。行政サイトは難解、個人ブログは古い |
| EigoCheckとの相乗効果 | 7/20 | 英語圏への渡航者は英語学習ニーズと一定の重複あり。EigoCheckユーザーへのクロスプロモーションが可能。英語での渡航書類記入サポートという拡張も考えられる |
| マネタイズ可能性 | 13/20 | 情報コンテンツへの課金は難しい。月額480円または買い切り980円が上限感。広告モデルも弱い。「行政書士・代行業者への送客アフィリエイト」が現実的な収益源 |

**なぜ今のオーナーに向いているか:**
実装が最もシンプルで、3ヶ月どころか3週間でMVPが作れる。EigoCheckと唯一の相乗効果（英語圏渡航者×英語学習）がある。ただしマネタイズが最も弱い。「サイドプロジェクト × 送客アフィリエイト」としては成立するが、月10万円達成は難しい。

**MVP設計案:**
- **最小機能**: 渡航予定日・渡航先国・ペット種（犬/猫）を入力 → 今日から渡航日まで逆算したタスクリストを自動生成（例：「渡航180日前：狂犬病抗体価検査を実施」）
- **技術スタック**: Swift/SwiftUI（iOS）またはHTML+JavaScript（Webツール）。データは国×ペット種のJSON。外部API不要
- **想定工数**: コンテンツ整理2週間（主要5ルートの情報収集）→ UI実装2週間 = 4週間
- **最初の収益化方法**: 無料公開 → PetAir JPN等の代行業者へのアフィリエイトリンク → 有料プランでカスタム国対応

**リスク・注意点:**
- 渡航規制は随時変わるため、情報の最新性維持がコストになる
- 「法的情報の正確性」について免責事項が必須
- 市場規模が小さく、月3〜10万円の収益化に最も時間がかかる見込み
