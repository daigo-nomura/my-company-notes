# アイデア精査レポート — 2026-10-04

## 総評

2026年10月時点での収集結果を見ると、「iOS 26 + AI搭載」の競争激化により汎用的なコンシューマーアプリは差別化が難しくなっている一方、特定ニッチ職種向けBtoBツールとEigoCheckの延長線上にある英語学習特化アプリは依然として空白地帯が多い。オーナーの業界インサイダー知識（運送業）を活かせるカテゴリが今回の最大の強みとなる。

## 🥇 第1位: ドライバー日報スマホ入力アプリ（大型トラック・路線便版）

**総合スコア: 80/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + iCloud/バックエンドAPI。CarryNoteの構成が参考になる。チャット形式UI＋PDF書き出しがメイン機能。3ヶ月で充分MVP可能 |
| 市場規模 | 16/20 | 中小運送会社（10〜50台）は全国で数万社。ドライバーは100万人超。ただし法人決裁が必要でB2B特有のリードタイム |
| 競合の少なさ | 18/20 | CarryNoteは軽貨物専門。大型・路線・チャーター向けの日報アプリはApp Storeで5件以下。直接競合はほぼなし |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層・スキルともに重複なし。ただしSwiftUI経験は流用可能 |
| マネタイズ可能性 | 19/20 | 月額980〜2,980円 × 10〜30台の会社が導入なら月3〜10万円達成は6ヶ月以内に現実的。「経費として計上できる」B2Bは解約率低い。業界知識で差別化しやすい |

**なぜ今のオーナーに向いているか:**
デジタコ・運行管理システムメーカー勤務により、ドライバーが日報に何を書くか・配車担当が何に困っているかを誰よりも知っている。これが最大の参入障壁。競合が「UI良いけど現場感ない」ツールになりがちな中、ユーザーインタビュー不要でプロダクトを設計できる。

**MVP設計案:**
- 最小機能: ①スマホでの日報入力（運行開始・終了・休憩・走行距離・積荷）②PDF書き出し（既存紙日報と同フォーマット）③月次集計グラフ
- 技術スタック: SwiftUI + PDFKit + Core Data（iCloud同期） + オプション: Supabase（法人管理）
- 想定工数: UIデザイン2週間 → 基本機能4週間 → テスト/審査2週間 = 約2ヶ月
- 最初の収益化方法: 月額980円（個人ドライバー）/ 法人プラン2,980円/台。導入会社のトラック台数分だけMRR増加

**リスク・注意点:**
- 法人への営業チャネルが必要（個人→AppStore流入のみでは難しい）。LinkedInや運送業者コミュニティへの発信が必須
- 法的要件（日報の保存義務・記載事項）を正確に把握して実装する必要あり（ただしオーナーは業界知識で対応可能）
- 「試してみて合わなければ解約」が可能な月額形態にしないと中小は入りにくい

## 🥈 第2位: 英語日記添削アプリ（EigoCheckの姉妹アプリ）

**総合スコア: 77/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | EigoCheckの添削APIロジックをほぼ流用可能。日記入力UI + AIフィードバック + カレンダー表示がメイン。2ヶ月で余裕でMVP可能 |
| 市場規模 | 15/20 | 英語日記学習者は英語学習人口（国内数百万人）のサブセット。熱量高いコアユーザーへのリーチしやすさが強み |
| 競合の少なさ | 17/20 | ライティング添削アプリはあるが「日記特化」はApp Storeで3件未満。Write & Improve（ケンブリッジ）は英語UIのみで日本人に使いにくい |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckユーザーへのクロスセルが最も自然。同じターゲット・同じAPI・既存ユーザーが「次に欲しいもの」と一致 |
| マネタイズ可能性 | 7/20 | 月額300〜500円帯が適正。ただしコンシューマーアプリで月3〜10万円達成は獲得ユーザー数が必要（300〜1,000人規模） |

**なぜ今のオーナーに向いているか:**
EigoCheckの開発で培ったAI添削のプロンプト設計・API統合・キーボード拡張の知識が完全流用可能。EigoCheckユーザーへの告知1本で初期ユーザーを獲得できる。技術的新規性ゼロなので確実に作れる。

**MVP設計案:**
- 最小機能: ①日記エディタ（文字数・語彙レベル表示）②AI添削（ネイティブ表現への書き換え提案）③ストリーク管理（連続日記日数）④週次フィードバックレポート
- 技術スタック: SwiftUI + OpenAI/Claude API + CloudKit（日記同期）
- 想定工数: UI設計1週間 → 添削機能2週間（EigoCheckから流用）→ 日記UI+カレンダー2週間 → テスト1週間 = 約6週間
- 最初の収益化方法: 月3件まで無料 → プレミアム月額480円（無制限添削 + 週次レポート）

**リスク・注意点:**
- コンシューマーアプリはアプリ内課金のコンバージョン率が低め（5〜15%）。EigoCheckの既存ユーザーリストへの展開が鍵
- AIコスト管理: 日記1件の添削コストを0.5〜2円に抑えないと利益率が出ない。プロンプトチューニング要
- mikan等の大手がライティング添削を強化中。動くうちに出す

## 🥉 第3位: 個人ネイリスト・一人サロン向け写真付きカルテ管理アプリ

**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 19/20 | SwiftUIで写真撮影・保存・検索UIが作れる。Core Data + iCloud Photos。最もシンプルなMVPが作りやすい |
| 市場規模 | 13/20 | ネイリスト人口は国内数万人。一人サロン・フリーランス率が高い。しかし月額を払う層はそのサブセット |
| 競合の少なさ | 16/20 | 無料のネイルカルテアプリが存在するが写真・在庫連携が弱い。月額課金の競合は少ない |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層が完全に異なる。スキル流用（SwiftUI）のみ |
| マネタイズ可能性 | 18/20 | 月額500〜1,000円でも十分な支払い意欲あり。解約率が低い（日常業務に組み込まれれば）。月100ユーザーで月5〜10万円 |

**なぜ今のオーナーに向いているか:**
機能がシンプルなのでSwiftUI初〜中級でも必ず完成できる。最初のBtoB収益化の「練習台」として最適。ユーザーコミュニティ（ネイリストのInstagram・X）が明確でテストマーケティングしやすい。

**MVP設計案:**
- 最小機能: ①顧客登録（名前・連絡先・アレルギー）②施術記録（日付・メニュー・使用カラー・写真）③次回予約メモ
- 技術スタック: SwiftUI + Core Data + iCloud Photos + PhotosUI framework
- 想定工数: UIデザイン1週間 → データモデル+CRUD2週間 → 写真管理1週間 → テスト1週間 = 約5週間
- 最初の収益化方法: 顧客50人まで無料 → プレミアム月額680円（無制限 + 写真無制限 + データエクスポート）

**リスク・注意点:**
- EigoCheckとのシナジーがないため、ユーザー獲得を一から始める必要がある
- 無料競合（既存のネイルカルテアプリ）との差別化を「写真+在庫+使いやすさ」でどこまで明確にできるか
- Googleスプレッドシートやノーション等の汎用ツールへの乗り換えリスク
