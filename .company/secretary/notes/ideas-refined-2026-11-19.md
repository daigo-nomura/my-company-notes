# アイデア精査レポート — 2026-11-19

## 総評

今回は「運送業界インサイダー」という強みが活きる傭車管理アプリが断然の首位。ペット渡航はニッチすぎる市場規模がネック、整体師向けカルテはLINEビューティープラスの対象外という好機があるが競合が少しずつ増えてきている。全体的に「オーナーが業界を知っているかどうか」がスコアを左右しており、EigoCheckのユーザー流用よりも「業界知識の流用」に優位性がある局面に入ってきた。

---

## 🥇 第1位: 傭車管理アプリ（中小運送会社向け）

**総合スコア: 71/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | SwiftUI + Supabase（またはCloudKit）で傭車台帳・外注依頼記録・月末精算計算のMVPは3ヶ月以内に可能。複雑なリアルタイム追跡は不要。シンプルなCRUD+計算で価値を提供できる |
| 市場規模 | 16/20 | 中小運送会社（10〜50台規模）は全国に数万社。傭車比率30%以上の会社に絞っても数千社規模。月額5,000〜10,000円で20〜50社契約なら月10〜50万円 |
| 競合の少なさ | 18/20 | App Storeで傭車管理単体アプリはほぼゼロ。大手システムは月10万円〜で中小には高すぎる。空白地帯 |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層・技術スタックとも重複なし。SwiftUIの経験は活きるが他はゼロから |
| マネタイズ可能性 | 18/20 | BtoBは解約率が低い。月末の傭車精算照合に「数時間→30分」になるROIが明確で稟議が通りやすい。月額5,000〜10,000円×20社で月10〜20万円を6ヶ月以内に達成できる見込みが高い |

**なぜ今のオーナーに向いているか:**
デジタコ×運行管理システムのメーカーに勤務していることで、傭車管理の実務フロー（配車依頼→実績確認→月末精算）を自分の目で見ている。ユーザーインタビューなしでも仕様が書ける。同業者・取引先を通じた初期ユーザー獲得もしやすい。競合参入コストが高い（業界理解が必要）ため、一度シェアを取ると安定する。

**MVP設計案:**
- 最小機能:
  1. 傭車先会社マスター（社名・連絡先・単価）
  2. 便ごとの傭車記録入力（日付・荷主・ルート・使用した傭車先・金額）
  3. 月ごとの傭車費用集計・CSV出力（Excel照合に使える形式）
  4. プッシュ通知（月末精算リマインド）
- 技術スタック: SwiftUI + Supabase（PostgreSQL）+ Swift Package Manager
- 想定工数: 2〜3ヶ月（MVPとして月末精算ができる状態）
- 最初の収益化方法: 無料14日間トライアル→月額5,000〜8,000円（1社）。まず知り合いの運送会社3〜5社に無料で使ってもらいフィードバックを得る

**リスク・注意点:**
- BtoBの営業力が必要：AppStoreだけでは見つけてもらえない。X・業界団体（全日本トラック協会系の地方支部勉強会）・LinkedIn経由の地道な営業が必要
- 本業との利益相反チェック：勤務先のシステムと機能が重複する場合、就業規則確認が必要
- データセキュリティ：運送情報は荷主情報を含む。セキュリティ設計（暗号化・アクセス制御）をMVPから考慮する

## 🥈 第2位: ペット海外渡航書類チェックリスト＆スケジューラー

**総合スコア: 69/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + ローカルデータ（国別要件JSON）+ 通知のみ。バックエンド不要でMVP可能。国別データを収集・入力する手間がかかるが、まず日本→アメリカ・オーストラリアの2ルートから始めれば1〜2ヶ月 |
| 市場規模 | 11/20 | 海外移住・長期赴任でペット連れの層は限定的。日本→海外のペット渡航は年間数万件規模と推測されるが、アプリを探す層はさらに絞られる。市場が小さいのが最大の弱点 |
| 競合の少なさ | 19/20 | App Storeでほぼ存在しない。官公庁サイトは使いにくく、代行業者サイトは有料サービス誘導型。ユーザーに寄り添ったチェックリストアプリは空白 |
| EigoCheckとの相乗効果 | 8/20 | 「語学・自己改善・海外志向」ユーザー層は少し重なる。英語の書類作成にEigoCheckを使う可能性。技術的流用はSwiftUIのみ |
| マネタイズ可能性 | 14/20 | 買い切り1,220円でストア内で目立てれば初月から収益化可能。ただし月3〜10万円を安定させるには大量ダウンロードが必要（3,000〜8,000件）。サブスク月額490円でも6,000人以上必要で規模感が合わない |

**なぜ今のオーナーに向いているか:**
iOS開発の練習台として最適。バックエンドなし・静的データ・通知という構成はSwiftUI初〜中級者向けの難易度。「書類の順序ミス」という痛点が明確で機能要件がブレない。ただし収益化のスケールが小さく、EigoCheck後の2本目としては規模感が合わない可能性がある。

**MVP設計案:**
- 最小機能:
  1. 渡航先の国選択（犬/猫の種別も）
  2. 必要書類チェックリスト（マイクロチップ→ワクチン→抗体検査の順序を明示）
  3. 出発日から逆算したカレンダー通知（「今日から始めないと間に合わない」アラート）
  4. 国別要件の要約（農林水産省動物検疫所情報を読みやすく整理）
- 技術スタック: SwiftUI + UserDefaults（進捗保存）+ UNUserNotificationCenter
- 想定工数: 1.5〜2ヶ月（日本→アメリカ・オーストラリアの2ルート対応）
- 最初の収益化方法: 買い切り600〜1,220円。ペット系Instagram・X・Yahoo知恵袋回答でオーガニック流入

**リスク・注意点:**
- 要件変化リスク：国別の渡航要件は頻繁に変わる（シンガポールが2026年4月に変更した実例あり）。データ更新コストが継続的にかかる
- 市場の狭さ：月3〜10万円の安定収益には市場が小さすぎる可能性。EigoCheckが軌道に乗った後の「副収入」として割り切るなら適切

## 🥉 第3位: 整体師・鍼灸師向けカルテ×予約一体管理アプリ

**総合スコア: 65/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 13/20 | CloudKitデータ同期・カレンダー予約管理・カルテ（写真+テキスト記録）が必要。3ヶ月のMVPとしては少し機能が多い。予約のリマインド通知・ダブルブッキング防止など細かいUXが重要で工数がかかる |
| 市場規模 | 15/20 | 整体院・鍼灸院は全国に数万院。個人経営が多く月額2,980〜3,980円を払う意欲ある層が十分存在。LINEビューティープラスの対象外なので今が参入チャンス |
| 競合の少なさ | 16/20 | 整体向けカルテ+予約の一体アプリは2〜3件（汎用予約アプリが一部対応）。LINEビューティープラスが2026年6月に開始したが美容室特化。隣接する整体・鍼灸に空白あり |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層・ドメイン知識ともに重複なし。SwiftUIの経験だけが共通 |
| マネタイズ可能性 | 17/20 | 月額2,980円×30人＝月8.9万円。6ヶ月で30人獲得は、整体師向けX・Instagram広告＋直接DMで現実的。解約率が低く安定収益になりやすい |

**なぜ今のオーナーに向いているか:**
LINEビューティープラスが美容室に集中した結果、整体・鍼灸に空白が生まれた。競合不在の今が最良のタイミング。ただし医療系に近い領域のため、GDPR・個人情報保護のカルテデータの扱いに注意が必要。

**MVP設計案:**
- 最小機能:
  1. 患者（クライアント）プロフィール管理（名前・生年月日・来院経緯）
  2. 施術カルテ記録（日付・施術内容・体の状態メモ・写真1〜3枚）
  3. 次回予約管理（カレンダー表示・リマインド通知）
  4. クライアントへのLINEメッセージ送信連携（URLスキームで自動テキスト挿入）
- 技術スタック: SwiftUI + CloudKit（マルチデバイス対応）+ EventKitまたは独自カレンダーUI
- 想定工数: 3〜3.5ヶ月（CloudKitのデータ設計に時間かかる）
- 最初の収益化方法: 無料30日間トライアル→月額2,980円。整体師コミュニティ（X・Instagram）への無料提供でレビュー獲得

**リスク・注意点:**
- 個人情報・医療隣接データ：施術記録は患者の身体情報を含む。セキュリティ設計・プライバシーポリシー・データ削除対応が必要
- LINEビューティープラスの整体業への拡張リスク：LINEが将来的に整体業に対応した場合、強力な競合になる
- 工数リスク：CloudKitとカレンダー管理の組み合わせが3ヶ月に収まるか要見積もり
