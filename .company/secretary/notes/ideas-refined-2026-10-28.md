## 🥇 第1位: EigoCheckスピーキング拡張「EigoSpeak」

**総合スコア: 84/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + Whisper API + Claude API。既存EigoCheckのコード・UI・StoreKit実装が流用できる。新規開発は音声録音→文字起こし→フィードバック生成のパイプラインのみ |
| 市場規模 | 18/20 | 2026年最注目カテゴリ。AIスピーキング練習は日本語フィードバック付きがほぼ存在しない。EigoCheckの既存ユーザーに告知できる |
| 競合の少なさ | 16/20 | ディアトーク、AI英会話Bunpo等が登場しているが「EigoCheck連携・テキスト添削→スピーキング練習ループ」は他にない |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckの自然な次のステップ。既存ユーザーへのクロスセル、コード流用、APIコスト構造が同じ |
| マネタイズ可能性 | 13/20 | EigoCheckのサブスクに音声練習機能を追加（上位プラン）またはスタンドアロンアプリ。ただしWhisper/Claude APIコスト増分の計算が必要 |

**なぜ今のオーナーに向いているか:**
EigoCheckで得たSwiftUI・Claude API・StoreKitの知識がそのまま使える。既存ユーザーへの告知チャネルも持っている。「書く→添削→声に出す」という学習ループはユーザーが自然に求めるものでプッシュ型の説明が不要。

**MVP設計案:**
- 最小機能: テキストを入力→Claude APIで例文生成→マイクで音読→Whisper APIで文字起こし→Claude APIで発音・流暢さフィードバック
- 技術スタック: SwiftUI + AVFoundation（録音）+ Whisper API（文字起こし）+ Claude API（フィードバック）
- 想定工数: 4〜6週間（API連携2週、UI実装2週、テスト・申請2週）
- 最初の収益化方法: EigoCheckの月額プランに音声練習機能を追加する上位プラン（月額600〜980円）、またはEigoSpeakとして単体無料+月額480円

**リスク・注意点:**
- Whisper APIの音声認識コストがユーザー数増加とともに増大する（1分あたり約0.006ドル。1日5分使うユーザー100人で月約9ドル。許容範囲）
- 発音の正確な評価は技術的に難しい（Whisperは認識を返すが発音の良し悪しは別の評価が必要。最初は「正確に読めているか」だけに絞る）

## 🥈 第2位: 中小運送会社向け傭車管理アプリ「YoshaKan」

**総合スコア: 76/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 14/20 | Web API（REST）+ シンプルなSaaS。バックエンドはSupabase等でMVP可。SwiftUIより先にWebアプリで出すほうが中小企業PCユーザーに刺さりやすい |
| 市場規模 | 15/20 | 中小運送会社（10〜50台）は全国数万社規模。2024年問題で急いでデジタル化したい会社が多い |
| 競合の少なさ | 20/20 | 「傭車管理」に特化した専用ツールはApp Store/Web双方でほぼ存在しない。完全な真空地帯 |
| EigoCheckとの相乗効果 | 5/20 | 技術スタック（Swift vs Web）もユーザー層も全く異なる。ゼロから始める |
| マネタイズ可能性 | 22/20 → 17/20 | 中小企業向けBtoBはchurnが低く月額1〜3万円/社が目安。ただし最初の数社獲得に業界人脈が必要 |

**なぜ今のオーナーに向いているか:**
業界インサイダーとして「傭車管理がFAX・電話・Excelで回っている現実」を肌で知っている。課題の深さを外部の開発者より正確に把握できる唯一の立場。既存の大手システムが対応していない「10〜50台規模の隙間」を正確に狙える。

**MVP設計案:**
- 最小機能: 傭車依頼の記録（便名・傭車先・金額）、月末精算レポートのPDF出力、傭車先マスタ管理
- 技術スタック: Web（Next.js + Supabase）またはSwiftUI（iOSアプリ）。配車担当がPCを使うことが多いのでWebを推奨
- 想定工数: 6〜10週間（要件定義2週、バックエンド3週、フロントエンド3週、テスト2週）
- 最初の収益化方法: 知り合いの運送会社に無料トライアル→フィードバック後に月額5,000〜10,000円で販売

**リスク・注意点:**
- 最初の数社獲得には業界人脈の活用が必須（BtoB営業スキルが必要）
- Webアプリ開発の場合、Swiftではなく別の技術スタックになる（Next.js等）
- EigoCheckとの相乗効果がゼロのため、完全に別の事業として考える必要がある

## 🥉 第3位: 家庭教師・個人塾向け管理＋請求書アプリ「JukuNote」

**総合スコア: 74/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUIのみで完結。CRUD + PDF生成 + CloudKit（データ同期）。技術的に最もシンプルなMVP |
| 市場規模 | 12/20 | 国内個人塾・家庭教師の市場は確実に存在するが規模は中程度。月額課金ユーザー数の上限が読みにくい |
| 競合の少なさ | 18/20 | StudentManagerは存在するが請求書機能なし。日本語対応で請求書まで出せるアプリはほぼ皆無 |
| EigoCheckとの相乗効果 | 10/20 | SwiftUIのUI コンポーネントやStoreKit実装は流用できる。ユーザー層は異なる |
| マネタイズ可能性 | 16/20 | 月額500〜800円程度のフリーミアム。確定申告前後にダウンロード数が増えるパターン狙える |

**なぜ今のオーナーに向いているか:**
SwiftUI習得の練習台として最適（CRUD + PDF生成はSwiftUI入門の定番題材）。競合空白が明確で「作れば使われる」確率が高い。EigoCheckの次のプロジェクトとして技術スキルを伸ばしながら収益化の感覚を掴める。

**MVP設計案:**
- 最小機能: 生徒プロフィール登録、出欠記録、月謝計算、請求書PDF出力
- 技術スタック: SwiftUI + CloudKit（iCloud同期）+ PDFKit（PDF生成）
- 想定工数: 4〜6週間（データモデル1週、UI実装3週、PDF生成1週、申請1週）
- 最初の収益化方法: 基本無料（生徒5人まで）→月額600円で無制限

**リスク・注意点:**
- ターゲット層（40〜60代の個人塾講師）のアプリ購入率が低い可能性
- freee等の会計ソフトと連携できないと「結局二重管理」になる
- App Storeでの集客に時間がかかる。ASO（App Store最適化）が重要
