# アイデア精査レポート — 2026-07-22

## 総評

今回の収集では、オーナーの「業界インサイダー」属性を活かした**運送業ニッチSaaS**、EigoCheckの技術資産を直接横展開できる**AI英語ライティング支援**、そして競合が薄い**個人習い事教室管理**の3軸で有望アイデアが集中した。いずれもSwift/SwiftUIとWeb APIのみで実装可能かつ3ヶ月以内MVP射程に入っており、今回の「作れる条件」フィルタを全て通過している。特に運送業ニッチは参入障壁として「現場知識」が機能するため、同業他者に模倣されにくい強みがある。

## 🥇 第1位: 傭車管理＋ドライバー日報アプリ（運送業界向け）

**総合スコア: 82/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + CloudKit（または Firebase）でMVP可能。傭車依頼記録・費用入力・日報入力の3画面が核心。GPSやデジタコ連携なしでも成立する |
| 市場規模 | 15/20 | 全国に6万社超の運送事業者。10〜50台規模の中小が多数。ただし1社あたり月額2000〜5000円×20〜50社が現実的スタート規模（最大月25万円）|
| 競合の少なさ | 19/20 | 傭車管理専用アプリはApp Storeにほぼ存在しない。大手ERPの一機能として埋もれており、単体・廉価アプリは市場の空白地帯 |
| EigoCheckとの相乗効果 | 8/20 | 英語学習との直接の相乗効果はないが、CloudKit・サブスク課金・業務アプリUXの知見は共通 |
| マネタイズ可能性 | 18/20 | 月額3000〜5000円×20社=月6〜10万円は6ヶ月以内に現実的。業界知人への直接セールスから始められる。BtoBで解約率が低い |

**なぜ今のオーナーに向いているか:**

最大の参入障壁が「現場知識」であり、それをオーナーはすでに持っている。傭車の精算フロー・点呼記録・日報の実態を知らない外部開発者では正確なUXが作れない。競合が参入しにくく、初期ユーザーを勤務先の知人ネットワークから獲得できる可能性がある（0→1の最難関を短絡できる）。

**MVP設計案:**

- **最小機能（3画面）**:
  1. 傭車依頼記録：日付・依頼先会社名・便名・金額・メモの入力＋一覧表示
  2. ドライバー日報：日付・走行距離・積み荷・出発/到着時刻・アルコールチェック結果の入力
  3. 月次集計：傭車費用の月合計・ドライバー別稼働時間の自動集計

- **技術スタック**: SwiftUI + CloudKit（iCloudで自動バックアップ）。追加機能はFirebase Firestoreで複数端末同期
- **想定工数**: UIプロトタイプ2週間 → コア機能実装4週間 → テスト・修正2週間 → TestFlight配布2週間 = 約2.5ヶ月
- **最初の収益化方法**: 無料トライアル30日 → 月額3000円（フリーミアムではなく全機能を有料）。勤務先知人3〜5社への初期テストユーザー獲得から

**リスク・注意点:**

- BtoB営業が必要。個人での営業活動と開発の両立が課題
- 勤務先との利益相反がないか確認が必要（同業向けSaaSを副業で作ることへの許可）
- 規制情報（点呼義務・アルコールチェック義務）の変化に合わせたアプリ更新が継続的に必要

## 🥈 第2位: 個人習い事教室管理アプリ（ピアノ・英語・ヨガ等の先生向け）

**総合スコア: 75/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUI + CloudKitのみで完結する最もシンプルな業務アプリ。生徒情報・月謝・スケジュールの3テーブルで成立 |
| 市場規模 | 14/20 | 個人レッスン先生は全国数十万人規模。ただし月額500〜1000円帯なので月収10万円には200人が必要。時間がかかる |
| 競合の少なさ | 16/20 | 「生徒ミル」「レッスン管理」等が数件あるが、保護者連絡機能付き・特定ジャンル特化はほぼ空白 |
| EigoCheckとの相乗効果 | 12/20 | 英語個人レッスンの先生はEigoCheckの潜在ユーザー層とオーバーラップ。英語教室先生向け特化なら自然なクロスセル |
| マネタイズ可能性 | 15/20 | 月額800円×200人=月16万円が6〜12ヶ月の現実的ゴール。フリーミアム（5人まで無料）で口コミ拡散を狙う |

**なぜ今のオーナーに向いているか:**

EigoCheckの英語学習ユーザーから「英語個人教室の先生」へのリーチが自然にできる。英語教室の先生にEigoCheckを勧め、同時に教室管理アプリを紹介するクロスセル戦略が成立する。実装難易度が最も低く、SwiftUI初〜中級でも3ヶ月以内に完成しやすい。

**MVP設計案:**

- **最小機能（4画面）**:
  1. 生徒一覧：名前・連絡先・月謝・入会日
  2. レッスン記録：日付・生徒選択・内容メモ・出席/欠席
  3. 月謝管理：月ごとの支払い状況（支払済/未払）と合計額
  4. 保護者への報告メッセージ生成（授業後に「今日やったこと」をテンプレから送信）

- **技術スタック**: SwiftUI + CloudKit。請求書PDF出力はPDFKit。保護者連絡はiOS標準のメール/SMS APIで送信
- **想定工数**: 2〜2.5ヶ月でMVP完成。最もスピード感を持って進めやすい
- **最初の収益化方法**: 5人まで無料（フリーミアム）→ 6人以上は月額800円。英語教室の先生コミュニティ（Facebookグループ等）で告知

**リスク・注意点:**

- 月額が低価格帯なため、ユーザー数を集めるのに時間がかかる
- 「生徒ミル」「レッスン管理」等の既存アプリとの差別化メッセージが必要（保護者連絡機能・特定ジャンル特化が差別化軸）
- 一般汎用管理アプリとして作ると競合に埋もれる。「英語個人教室の先生向け」に絞ることが重要

## 🥉 第3位: ビジネスメール英語生成キーボード（EigoCheckの横展開）

**総合スコア: 72/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | EigoCheckのKeyboard Extension実装がそのまま流用できる。Claude/OpenAI APIコールの変更だけでMVP可能。最短1〜1.5ヶ月 |
| 市場規模 | 14/20 | 日本のビジネスパーソンで英語メールを書く人は数百万人。ただしGrammarlyの存在が強く、差別化が課題 |
| 競合の少なさ | 13/20 | Grammarlyは英語ネイティブ向けで日本語UIが弱い。「日本語で書いた文章を英語ビジネスメールに変換」特化は競合が少ない |
| EigoCheckとの相乗効果 | 19/20 | コードの8割が流用できる。EigoCheckユーザーへの告知がそのままマーケティングになる。既存の審査実績でApp Store審査も通りやすい |
| マネタイズ可能性 | 10/20 | 月額480〜980円で個人向け、月額2000円でビジネス向け。ただしGrammarlyが無料でカバーしている機能と競合するため、差別化なしでは苦戦 |

**なぜ今のオーナーに向いているか:**

最もリスクが低く最短で出せる選択肢。EigoCheckの既存コードを活かせるため「追加開発」に近い感覚で進められる。EigoCheckでApp Storeのキーボードカテゴリを知り尽くしているため、審査上のリスクも把握済み。

**MVP設計案:**

- **最小機能（2モード追加）**:
  1. 「日本語→英語ビジネスメール変換」モード：日本語の文章をキーボードで選択 → 英語ビジネスメールに変換して挿入
  2. 「英語添削 + 理由説明」モード：EigoCheckの現機能に「なぜ間違っているか」の説明を追加

- **技術スタック**: EigoCheckの既存コード + Claude API（claude-haiku-4-5推奨、低レイテンシ・低コスト）
- **想定工数**: 1〜1.5ヶ月でMVP。既存コードの流用率が高い
- **最初の収益化方法**: EigoCheckのアップデートとして無料追加 → プレミアムプランとして月額480円。既存ユーザーへのインアップ購入促進

**リスク・注意点:**

- Grammarlyのブランド認知が強く、新規ユーザー獲得のCACが高い
- APIコスト（生成のため添削より高い）が収益を圧迫するリスク
- 「ビジネスメール英語生成」は需要は確実にあるが、既存のChatGPTアプリでも代替できるため「キーボードの利便性」が差別化軸になる
