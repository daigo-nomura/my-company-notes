# アイデア精査レポート — 2026-07-31

## 総評

今回の収集で浮かび上がった最大のテーマは「業界インサイダー優位性の活用」と「AI添削のコモディティ化への対応」の2つ。Duolingoがエネルギーシステム刷新で失ったユーザー層と、物流2026年問題以降のIT化義務化という2つの波が重なり、短期収益化の好機が存在する。ただし英語学習アプリはAI会話機能の当たり前化により単純添削の差別化が難しくなっており、EigoCheckの次の一手として「ビジネス英語×キーボード」か「完全異ジャンル（傭車管理等）」かの方向性判断が急務。

## 🥇 第1位: 傭車（外注）管理アプリ「ユシャ管」（仮称）

**総合スコア: 86/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | CRUD + PDF出力 + 月次集計のみ。SwiftUI初〜中級者が3ヶ月以内に完成できる範囲。オフライン対応は必須だが複雑ではない |
| 市場規模 | 14/20 | 国内中小運送会社（10〜50台）は約3万社規模。全社が潜在顧客ではないが、傭車を使う会社は多い。単価が高い（月5,000〜15,000円）ので顧客数少なくても達成可能 |
| 競合の少なさ | 20/20 | App Storeで傭車管理単体アプリはほぼ0件。完全なブルーオーシャン |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層がまったく異なる。コード・スキルの流用は限定的。ただしSaaS運営スキルは転用可能 |
| マネタイズ可能性 | 26/20→上限20 | 月額8,000円×15社=月12万円が6ヶ月以内に現実的（オーナーの業界人脈で初期ユーザー獲得可能。BtoBは低チャーン）。上限超のため20点 |

**なぜ今のオーナーに向いているか:**
デジタコ・運行管理システムメーカー勤務という業界インサイダー優位性が直接活きる。「月末照合に丸1日かかる」という痛みを自分ごととして理解できる。見込み顧客への直接アクセスが勤務先ネットワーク経由で可能（中小運送会社の社長は直決裁が多い）。App Storeにほぼ競合がなく、初期の営業先1〜5社からのフィードバックで急速改善できる。

**MVP設計案:**
- 最小機能:
  1. 傭車会社マスタ管理（会社名・連絡先・単価設定）
  2. 便別傭車割り当て記録（日付・区間・傭車会社・依頼金額）
  3. 月次集計レポート（傭車会社別・合計金額）
  4. PDF出力（月次精算書として傭車会社に送付）
- 技術スタック: SwiftUI + Core Data（オフライン対応） + PDFKit（Apple純正）。バックエンドなしでもMVP成立
- 想定工数: UI設計2週間・CRUD実装3週間・PDF出力1週間・テスト1週間=計7週間（余裕を持って3ヶ月以内）
- 最初の収益化方法: 勤務先ネットワークから3〜5社に月額5,000円でベータ導入 → 30日無料トライアル → 月額8,000円の本番プラン

**リスク・注意点:**
- デジタコメーカー（勤務先）との競合・利益相反のリスク確認が必要。副業規定の確認も
- 法人営業が必要（個人ユーザーと違い意思決定に時間がかかる）
- 運送業の規制変更（法改正）への追従が必要（ただし傭車管理の本質機能は法規制に左右されにくい）
- 導入後のサポート負荷：BtoBアプリはサポート要求が多くなる傾向

## 🥈 第2位: ハンドメイド作家向け原価管理アプリ「テテコスト」（仮称）

**総合スコア: 76/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 19/20 | 材料在庫管理・原価計算・注文管理のCRUD。SwiftUI + CloudKitで完結。minne API連携はオプション扱いでMVPには不要 |
| 市場規模 | 16/20 | minne登録作家80万人超（推定）。そのうちiPhoneユーザーで売上管理に課題を持つ層は数万人規模。月額500円×5,000人=月250万円が理論上の上限 |
| 競合の少なさ | 18/20 | iOS専用の原価計算特化アプリはほぼ0件。Webサービスのみ（モバイル最適化なし） |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層は異なるが、個人向けサブスク運営・App Store最適化のスキルが流用可能 |
| マネタイズ可能性 | 15/20 | 月額500〜1,000円が上限。ユーザー数が必要。6ヶ月以内に月3万円は達成可能だが10万円には数千人が必要 |

**なぜ今のオーナーに向いているか:**
CRUDアプリとして技術的にEigoCheckより簡単。SwiftUI学習の延長線上で作れる。対象ユーザーが日本語話者のiOSユーザー（得意領域と一致）。競合がWeb版のみで「iOS最適化されたシンプルアプリ」としての差別化が明確。

**MVP設計案:**
- 最小機能:
  1. 材料マスタ（名前・単価・在庫数）
  2. 作品登録（材料×使用量で原価自動計算）
  3. 売上記録（販売価格入力→利益率自動表示）
  4. 月次サマリー（売上・原価・利益の一覧）
- 技術スタック: SwiftUI + CloudKit（iCloud同期）。WidgetKit でダッシュボードウィジェット追加で差別化
- 想定工数: 設計1週間・実装4週間・UI磨き2週間・審査提出1週間=計8週間
- 最初の収益化方法: 買い切り480円で初期評価獲得 → App内課金でCSVエクスポート・複数デバイス同期を有料化

**リスク・注意点:**
- ユーザー獲得がオーガニック（SEO・SNS）に依存するため時間がかかる
- minne/Creemaの公式APIが整備されていない場合、データ取り込みが手動になりUXが落ちる
- 単価が低いため、数でカバーする必要があり初期は収益が出にくい

## 🥉 第3位: ビジネス英語添削キーボード（EigoCheck拡張版）

**総合スコア: 71/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | EigoCheckの既存コード（キーボードExtension・API連携）をほぼ転用可能。新規開発量が最小 |
| 市場規模 | 15/20 | ビジネス英語を使う日本語話者は数十万人規模。「Slack/メールの英語が心配」層は特に多い |
| 競合の少なさ | 12/20 | Grammarlyが存在するが「日本人向け」特化で差別化可能。ただし認知度に大きなハンデ |
| EigoCheckとの相乗効果 | 19/20 | 既存ユーザーへの追加機能として提供可能。コード転用率が最も高い。同じユーザー層 |
| マネタイズ可能性 | 8/20 | Grammarlyが無料版を持つ中での差別化が難しい。月額課金への誘導ハードルが高い |

**なぜ今のオーナーに向いているか:**
EigoCheckの延長線上で開発できるため、ゼロからの学習コストが最小。既存ユーザーへの価値提供が即時可能。SwiftUIキーボードExtensionのスキルを完全流用。

**MVP設計案:**
- 最小機能:
  1. ビジネスメール/Slack文の添削（EigoCheckと同一エンジン）
  2. 「日本語英訳→ビジネストーン調整」機能（EigoCheckにはない新機能）
  3. よく使う表現のテンプレート保存（ビジネスメール特化）
- 技術スタック: 既存EigoCheckキーボードExtension + Claude API / OpenAI API（ビジネスプロンプト特化）
- 想定工数: 既存コード転用で2週間・新機能追加2週間・審査1週間=計5週間（最短）
- 最初の収益化方法: EigoCheck既存ユーザーへ月額追加300円のビジネスプランとして提供

**リスク・注意点:**
- Grammarlyという大手競合の存在（ただし「日本人向け」という差別化軸は有効）
- ビジネスユーザーはセキュリティ懸念から入力内容をサードパーティに送ることを嫌う層あり
- AI添削のコモディティ化が急速に進んでいる（2026年7月時点でDuolingo MaxもAI添削標準搭載）
