## 🥇 第1位: 英語音読採点・シャドーイング評価 iOS アプリ（EigoCheck 横展開）

| 評価軸 | スコア | コメント |

| 実装難易度 | 18/20 | SwiftUI + AVFoundation（録音）+ OpenAI Whisper API（発音評価）= EigoCheck と同一技術スタック。新規学習ゼロ。2ヶ月でMVP可能 |
| 市場規模 | 16/20 | スタディサプリが「コピーキャット（抑揚可視化）」を新機能追加→市場ニーズを大企業が証明済み。英語学習アプリ市場は国内数百万人規模 |
| 競合の少なさ | 14/20 | 「シャドーイング採点 × 日本人向け」特化はApp Storeで3件以下。Grammarly・スタディサプリと直接競合しないポジショニングが可能 |
| EigoCheckとの相乗効果 | 19/20 | OpenAI API連携・日本語UI・英文解析プロンプトがそのまま流用可能。EigoCheckの「書く」に対して「話す・読む」フローを追加する形なのでユーザーが重複 |
| マネタイズ可能性 | 13/20 | フリーミアム。月額480〜680円で月100ユーザー達成で月5〜7万円。EigoCheckのユーザー基盤からの誘導で初速が出やすい。ただし英語アプリの有料転換率は低め（〜3%）が課題 |

**なぜ今のオーナーに向いているか:**
EigoCheckで蓄積したOpenAI API連携・iOS開発スキル・英語学習ユーザーとのコミュニケーションが100%流用できる。「書く→話す」という自然な拡張であり、同じユーザー層に「次の一手」として提案できる。Apple のSpeechフレームワーク + Whisper API の組み合わせはチュートリアルが豊富で、初〜中級Swiftでも実装可能。スタディサプリという大手が同機能を追加した事実が「ニーズの証明」になっている。

**MVP設計案:**
- 最小機能:
  - 英語テキスト（手入力 or AI生成の例文）を表示
  - 「録音」ボタンを押して音読
  - Whisper API で文字起こし → オリジナルテキストとの一致率・発音スコアを表示
  - 間違えた単語をハイライト + 再挑戦ボタン
- 技術スタック: SwiftUI + AVFoundation + OpenAI Whisper API（音声→テキスト）+ GPT-4o（発音フィードバック生成）
- 想定工数: 6〜8週間（EigoCheckのAPI連携部分を流用するため短縮可能）
- 最初の収益化方法: 月10回無料→超過は月額480円のサブスク。EigoCheckのリリースと同時またはその直後に App Store 公開

**リスク・注意点:**
- Whisper APIのコスト：音声1分あたり約0.006ドル。無料ユーザーが多いとAPI費用が先行するため、無料枠は「1日3回まで」など制限が必要
- 英語学習アプリは離脱率が高い。ストリーク（連続学習）機能など継続施策をMVPに含めると差別化になる
- EigoCheckのリリース前に横展開を始めると集中力が分散するリスク → EigoCheckリリース後1ヶ月で着手が推奨

## 🥈 第2位: 中小運送会社向け「点呼記録＋日報」iOS アプリ
**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + CloudKit（データ同期）+ PDF出力。ドライバー側：スマホで日報入力。管理者側：iPad/PCで確認。2〜3ヶ月でMVP。フォーム系アプリで複雑なアルゴリズム不要 |
| 市場規模 | 16/20 | 国内中小運送会社（10〜50台規模）は数万社。全社が点呼記録義務あり。法改正プレッシャーで2026年に導入検討が加速中 |
| 競合の少なさ | 16/20 | 高価格帯（月額数十万円）の大手システムはあるが「月額2,000〜5,000円の軽量版」は空白。点呼記録特化のApp Storeアプリは数件のみで低評価が多い |
| EigoCheckとの相乗効果 | 4/20 | 技術的共通点ほぼなし。ただし「シンプルなフォームアプリ×CloudKit同期」という開発パターンはiOS基礎として習得済みの範囲 |
| マネタイズ可能性 | 18/20 | **BtoB月額課金の威力が最大**。月額3,000円×30社=月9万円。月額5,000円×20社でも月10万円。解約率が低い（業務ツールは一度定着すると動かない）。6ヶ月以内の目標月収3〜10万円が最も達成しやすい |

**なぜ今のオーナーに向いているか:**
業界インサイダーとしての知識が他の開発者には絶対に真似できない参入障壁になる。「点呼記録の何が面倒か」「監査で何を見られるか」「ドライバーがどんなUIなら使うか」を知っているのは業界経験者だけ。既存システムの欠点（高すぎる・複雑すぎる）を正確に把握しており、「ちょうどいい機能量」の設計ができる。

**MVP設計案:**
- 最小機能:
  - ドライバー：出発前点呼（アルコール値入力・体調確認チェック）→ CloudKit に保存
  - ドライバー：帰庫後日報（走行距離・乗務時間・特記事項）→ スマホから入力
  - 管理者（iPad/Web）：日別一覧表示 → PDF 出力（監査書類として使用可能）
  - ドライバー登録・車両登録・会社設定
- 技術スタック: SwiftUI（iOS + iPad）+ CloudKit（リアルタイム同期）+ PDFKit（帳票出力）
- 想定工数: 10〜12週間（CloudKitの設計が要で最初の1〜2週間はここに集中）
- 最初の収益化方法: ドライバー5人まで無料→それ以上は月額3,000円/社。SNS（X）で運送業界クラスタに直接DM営業可能。オーナーの職場コネクションが最初の3〜5社の獲得に使える

**リスク・注意点:**
- 営業チャネルの開拓：個人開発者が中小運送会社に売るのは初回が難しい。オーナーの職場・人脈を最大活用するか、物流系の情報サイトでSEO集客が必要
- 競合の大手が低価格版を出すリスク：ただし大手は「機能削減版」を作るインセンティブが薄いため現実的な脅威は低い
- 法改正への追従：点呼の法的要件が変わった際にアプリの更新が必要（継続的な業界知識の維持が必要）
- SwiftUI × CloudKit のマルチデバイス同期は初〜中級Swiftでは最難関部分。最初の2週間を完全にここに集中すること

## 🥉 第3位: ハンドメイド作家向け「在庫×原価計算」iOS アプリ
**総合スコア: 67/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + Core Data + iCloud同期。材料マスタ→商品レシピ→在庫自動計算のデータモデル設計が肝だが、複雑なAPIなし。2ヶ月でMVP可能 |
| 市場規模 | 13/20 | minne登録クリエイター数は100万人超だが、アプリに月額課金する層は一部。BtoCなのでユーザー数は多いが単価が低い |
| 競合の少なさ | 18/20 | App Storeで「ハンドメイド 原価計算」専用アプリは実質ゼロ。Excelテンプレートで代用されており、スマホアプリ化の空白が完璧 |
| EigoCheckとの相乗効果 | 6/20 | ユーザー層が完全に別。技術的にはCore Dataの基礎が活かせる程度。EigoCheckとの連携・流用はほぼなし |
| マネタイズ可能性 | 13/20 | 月額500〜800円×200ユーザー=月10〜16万円は理論値として可能。ただし作家層は「無料で当然」意識が強く有料転換率が低い可能性。買い切り980〜1,480円の方が転換しやすいかも |

**なぜ今のオーナーに向いているか:**
データモデルが「材料→レシピ→商品→在庫→売上」とシンプルで、Core Dataの練習にもなる。App Storeの競合空白が最も明確なカテゴリ。英語知識不要・業界知識不要で、Swiftの学習と収益化を同時に達成できる「練習台と本番の中間」的な位置づけ。

**MVP設計案:**
- 最小機能:
  - 材料登録（名前・単価・単位）
  - 商品レシピ設定（材料×使用量で原価を自動計算）
  - 在庫数の加減算（材料入荷・商品販売）
  - 販売価格入力→利益率自動表示
  - minne/BASE の手数料を加味した実質利益計算
- 技術スタック: SwiftUI + Core Data + iCloud（バックアップ用途）
- 想定工数: 7〜8週間
- 最初の収益化方法: 商品登録5点まで無料→買い切り1,480円で制限解除。minne の作家コミュニティ（SNS）で口コミ誘導

**リスク・注意点:**
- マネタイズ単価が低いため、月10万円達成には相当数のユーザーが必要（買い切り1,480円なら68ダウンロード）
- EigoCheckとの相乗効果がほぼないため、事業の多角化にはなるが「次の一手」としての連携が弱い
- minne側が公式に在庫管理機能を強化した場合に差別化が失われる
