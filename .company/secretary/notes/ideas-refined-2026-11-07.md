# アイデア精査レポート — 2026-11-07

## 総評

今回収集したアイデアは「業界インサイダーとしての優位性」と「EigoCheckの既存スキル活用」の2軸でくっきりと分かれた。傭車管理アプリは競合空白×業界理解×Swift単体実装可能という三拍子が揃っており、EigoCheckと並行して動かせる可能性がある。英語学習周辺では「ロック画面ウィジェット×英語フレーズ」がEigoCheckの既存コード・ユーザーを最大活用できるアイデアとして浮上した。

## 🥇 第1位: 傭車管理シンプルアプリ（仮称: Yosha / 傭車くん）

**総合スコア: 83/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUI + CloudKitのみで完結。傭車先マスタ・発注記録・月次精算のCRUDが主機能。UI設計が難しくなく、3ヶ月以内のMVP完成は現実的 |
| 市場規模 | 14/20 | 中小運送会社（10〜50台）は日本全国に数万社ある。ただし意思決定者にリーチするのに時間がかかる可能性あり |
| 競合の少なさ | 20/20 | App Storeに傭車管理専用アプリはほぼ存在しない。大手配車システムには機能として内包されているが独立した軽量ツールがない |
| EigoCheckとの相乗効果 | 10/20 | ユーザー層がまったく異なるため相乗効果は限定的。ただしSwiftUIのコンポーネント・CloudKitの設計はそのまま流用できる |
| マネタイズ可能性 | 20/20 | BtoBは解約率が低い。月5,000〜10,000円の設定でも10〜20社が使えば月5〜20万円。業界インサイダーとして初期ユーザーを口コミで獲得できる可能性が高い |

**なぜ今のオーナーに向いているか:**
デジタコ・運行管理システムメーカーに勤務しており、傭車管理のペインを「実務レベルで」理解している。競合にいる大手システム開発者は傭車担当者の日常業務を体感的に知らないが、オーナーは知っている。この非対称性がプロダクトの質に直結する。

**MVP設計案:**
- 最小機能: ①傭車先登録（社名・連絡先）②発注記録（日付・便・金額）③月次精算レポート出力（PDF or CSV）
- 技術スタック: SwiftUI + Core Data（ローカル）→ iCloud同期（CloudKit）
- 想定工数: MVP 6〜8週間（UIシンプルなCRUDが主体のため）
- 最初の収益化方法: 無料（〜10件まで）+ 月額980〜2,980円のフリーミアム。初期は口コミ・X発信で身近な運送会社に使ってもらう

**リスク・注意点:**
- BtoB法人への営業は意思決定が遅い。まず「個人事業主の運送業者」向けに絞ってBtoCに近い形でスタートする
- 競合が少ない＝市場が小さい可能性もある。まずβユーザー5〜10名のヒアリングで需要を確認してからフル開発

## 🥈 第2位: 英語フレーズ × ロック画面ウィジェット（EigoWidgetまたはEigoCheckの機能拡張）

**総合スコア: 78/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | WidgetKit + SwiftUIで完結。ロック画面ウィジェットはiOS 16以降の標準API。難しいロジックがなく2〜4週間でMVP可能 |
| 市場規模 | 16/20 | 英語学習アプリ市場は大きい。日本人英語学習者は数百万人規模。EigoCheckの既存ユーザーへのアップセルも可能 |
| 競合の少なさ | 14/20 | 英語学習ウィジェット自体は存在するが、「今日添削した表現をロック画面に表示」という連携型は少ない |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckそのものの機能拡張として自然に位置づけられる。既存ユーザーへのアップデートで提供可能。開発コスト最小 |
| マネタイズ可能性 | 10/20 | 単独アプリとしての収益化は難しい。EigoCheckのPremiumプラン追加機能として月額300〜500円の価値を加える形が現実的 |

**なぜ今のオーナーに向いているか:**
EigoCheckの開発者として、キーボード拡張・AI APIとの接続・日本語ユーザー向けオンボーディングのノウハウが蓄積されている。ウィジェットはその延長線上で最小工数で実装できる。既存ユーザーへのアップデートで即座に使ってもらえる点も強い。

**MVP設計案:**
- 最小機能: ①EigoCheckで添削した表現のうち、ユーザーが「覚えたい」とマークしたものをロック画面に表示 ②表示頻度・タイミングの設定
- 技術スタック: WidgetKit + SwiftUI（EigoCheckと同じXcodeプロジェクト内に追加）
- 想定工数: 2〜4週間（既存コードベースへの追加なので効率的）
- 最初の収益化方法: EigoCheck Premiumプラン（月額480円）の追加機能として提供

**リスク・注意点:**
- 単独アプリとして成立しないため、EigoCheckの完成度・ユーザー数が前提条件
- ロック画面ウィジェットは競合（Calendarly等）が増えているため、「英語添削連携」という固有の差別化が必要

## 🥉 第3位: ネイリスト×施術写真カルテ管理アプリ（仮称: NailBook）

**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + Core Data + カメラAPIで完結。写真の撮影→顧客紐付け→閲覧のUXが主体。3ヶ月以内のMVPは十分可能 |
| 市場規模 | 14/20 | 日本のネイリスト数は数万人。フリーランス・個人サロンも多い。ただし1人当たりの支払い意欲が職人業種は低めな場合も |
| 競合の少なさ | 16/20 | 汎用サロンアプリは多いが「ネイリスト1人のカルテ×写真」に特化したアプリは少ない。Nailieは予約マーケットプレイスで方向性が異なる |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層・技術スタックとも接点が薄い。コードの一部（CoreData設計など）は流用可能 |
| マネタイズ可能性 | 20/20 | 月額980〜1,980円の設定でフリーランスネイリスト50〜100人が使えば月5〜20万円。解約率が低いBtoC-BtoBの中間業種 |

**なぜ今のオーナーに向いているか:**
iOSのカメラAPIとSwiftUIの得意分野に合致している。職人業種向けのシンプルなUI設計は「動くMVP優先」の開発スタイルと相性が良い。

**MVP設計案:**
- 最小機能: ①顧客登録（名前・来店日）②施術写真の撮影・保存・顧客紐付け ③施術メモ（使ったカラー・デザインの記録）
- 技術スタック: SwiftUI + Core Data + iCloud Sync + AVFoundation（カメラ）
- 想定工数: 8〜10週間
- 最初の収益化方法: 無料（顧客10名まで）+ 月額980円のフリーミアム。ネイリスト向けX/Instagramで発信

**リスク・注意点:**
- 既存の「LiME」「minimo」との差別化を写真特化で出せるかが鍵
- ネイリストコミュニティへのリーチ（X/Instagram）が必要で、マーケティングがゼロから
- EigoCheckとユーザー層が重ならないため、両立させると集中力が分散する懸念
