## 総評

今回は英語学習・ペット渡航・運送業ニッチ・BtoBニッチSaaSの4領域から収集した。EigoCheckとの相乗効果を優先すると英語日記AI添削アプリが頭一つ抜ける一方、オーナーの業界インサイダー知見を活かすなら傭車管理アプリが競合空白×高単価の最強ポジションを持つ。ペット渡航アプリは実装が最も簡単だが市場規模が小さく、月3〜10万円の達成に時間がかかるリスクがある。

**総合スコア: 80/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | SwiftUIで日記UIを作り、Claude/GPT APIで添削。EigoCheckのAPIリクエスト処理・差分表示ロジックがほぼそのまま流用可能。キーボード拡張不要でシンプル。3ヶ月以内MVP確実 |
| 市場規模 | 15/20 | 日本の英語学習アプリ市場は年間数百億円規模。AI添削×日記特化は競合が比較的少ないポジション。潜在ユーザーはEigoCheckと同一層 |
| 競合の少なさ | 13/20 | Grammarlyはキーボード型、Speakは会話型。「毎日英作文を書いてAIが添削する」スタンドアロン日記アプリはApp Storeで数件のみ。完全空白ではないが差別化余地あり |
| EigoCheckとの相乗効果 | 20/20 | 既存EigoCheckユーザーへの最自然な横展開。コード（API通信・差分表示）・スキル（SwiftUI・Claude API）・ユーザーを全て流用可能。EigoCheck内からの誘導も可 |
| マネタイズ可能性 | 15/20 | 月額980〜1,480円のフリーミアム。英語学習市場は有料化率が他カテゴリより高い。ただし無料競合が多く、500ダウンロード → 有料転換まで3ヶ月以上かかる可能性 |

**なぜ今のオーナーに向いているか:**
EigoCheckで培ったSwiftUI・Claude API・英語添削ロジックをほぼそのまま転用できる唯一のアイデア。新しいスキルをゼロから習得する必要がなく、Swift初〜中級のソロ開発者でも確実に3ヶ月以内にMVPが完成する。EigoCheckユーザーへのクロスセルで初期ユーザー獲得コストもほぼゼロ。

**MVP設計案:**
- **最小機能**: 毎日の英作文入力（300字以内）→ Claude APIが文法・語彙・自然さを3点で添削 → カレンダービューで継続日数を可視化するストリーク機能
- **技術スタック**: SwiftUI + Claude API（Haiku-4.5でコスト最適化）+ CloudKit（日記データ保存）。バックエンドサーバー不要
- **想定工数**: UIデザイン2週間 → API連携1週間 → ストリーク/通知機能1週間 → TestFlight・審査2週間 = 計6〜8週間
- **最初の収益化方法**: 月10件まで無料 → 月額980円（Pro）で無制限添削。App Store In-App Purchase。EigoCheckアプリ内バナーで誘導

**リスク・注意点:**
- Claude/GPT APIのコストが1リクエスト当たり0.1〜0.5円程度かかる。無料ユーザーが多いとAPI費用が先行する可能性あり → 無料枠を月10件に絞ることでコントロール
- 英語学習アプリは離脱率が高い（習慣化が難しい）。ストリークとプッシュ通知の設計が継続率の生命線
- Grammarlyが日本語UIを強化した場合、差別化が薄れる可能性 → 「日本人が陥りがちな文法ミスに特化した添削」という差別化軸で対応

## 🥈 第2位: 傭車管理・精算照合アプリ（中小運送会社向け）

**総合スコア: 70/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 13/20 | SwiftUI + Supabase REST で実装可能。ただし業務フロー（便番号・荷主・傭車会社・金額）のデータモデルが複雑。3ヶ月でMVPは可能だがタイト。テスト先の確保が前提 |
| 市場規模 | 15/20 | 全国6万社の運送会社のうち傭車を使う中小（10〜50台）は数万社規模。月1〜3万円の課金なら10社で月10〜30万円。スモールスタートとしては十分な市場 |
| 競合の少なさ | 20/20 | App Storeで傭車管理単体アプリはほぼ存在しない。大手システムには機能が埋もれているが、単体・安価・シンプルなアプリは完全空白 |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層・コード・スキルセットがまったく異なる。SwiftUIの経験のみ流用可 |
| マネタイズ可能性 | 18/20 | BtoBは月1〜3万円の課金許容が高い。5社で月5〜15万円、10社で月10〜30万円。業界人脈でテスト導入先を1〜2社確保できれば6ヶ月以内の収益化が現実的 |

**なぜ今のオーナーに向いているか:**
デジタコ×運行管理システム勤務というインサイダー知識が最大の武器。業界の痛点（傭車精算の月末地獄・FAX照合）を体感として理解しており、UIと機能設計に無駄がない。同業他社へのテスト導入打診も人脈で可能。競合空白×高単価×インサイダー優位の三拍子が揃う。

**MVP設計案:**
- **最小機能**: 便登録（荷主・日付・ルート・傭車会社・単価）→ 月次集計 → 傭車会社別請求書PDF出力。これだけでFAX照合地獄を解消できる
- **技術スタック**: SwiftUI（iOS） + Supabase（PostgreSQL・REST API）。PDF出力はSwift標準のPDFKit。月額課金はRevenueCat
- **想定工数**: データモデル設計2週間 → CRUD UI実装2週間 → PDF出力1週間 → テスト導入・フィードバック反映2週間 = 7〜9週間
- **最初の収益化方法**: 1社に無料でテスト導入 → フィードバック反映後、月額9,800〜29,800円で正式課金。3社で月3〜9万円

**リスク・注意点:**
- BtoBは法人営業が必要。テスト導入先を業界人脈で確保できないと孤立したアプリになりかねない
- 会社の業務で知り得た情報や競合他社との利益相反がないか就業規則を事前確認すること
- 運送業の業務フローは会社によって微妙に異なる（荷主との契約・単価体系）→ MVP段階では「最もシンプルな構成」に絞ることが重要
- EigoCheck開発と並行するには工数が厳しい。EigoCheckを先にリリースしてから取り組む順序が望ましい

## 🥉 第3位: ペット渡航書類管理チェックリストアプリ

**総合スコア: 61/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUI + 静的JSONデータ（国別チェックリスト）。バックエンドAPIもCloudKitも最小限でOK。iOS開発初〜中級者でも最も完成させやすい |
| 市場規模 | 12/20 | 日本から年間数万件のペット渡航が推定されるが絶対数は少ない。Reddit・英語圏ではグローバルな需要があるため英語版も出せると大きくなる |
| 競合の少なさ | 18/20 | 日本語対応の専用アプリはほぼゼロ。農水省サイトは正確だが使いにくい。情報の整理・チェックリスト化という切り口で明確な差別化が可能 |
| EigoCheckとの相乗効果 | 3/20 | ほぼなし。ユーザー層・コード・スキルの流用はSwiftUI程度のみ |
| マネタイズ可能性 | 10/20 | 買い切り480〜980円 or 無料+広告。月額は難しい。絶対数が少ないため月3〜10万円の達成に6ヶ月以上かかる可能性。英語版のグローバル展開で市場を拡大できれば改善余地あり |

**なぜ今のオーナーに向いているか:**
技術的には最もシンプルで失敗しにくい。EigoCheckのリリース後に「副産物」として軽く作れるくらいのボリューム感。ただしメインビジネスとして月3〜10万円を目指すには市場規模が厳しい。

**MVP設計案:**
- **最小機能**: 出発国（日本）× 目的国 × ペット種（犬/猫）を選択すると手順チェックリストが表示される。各ステップに解説と注意点、公式リンク付き
- **技術スタック**: SwiftUI + ローカルJSON（国別データ）。CloudKitでチェック済み状態を保存。サーバーレス
- **想定工数**: データ収集・JSON化3週間 → SwiftUI実装3週間 → App Store審査2週間 = 計8週間
- **最初の収益化方法**: 基本無料（3ルートまで）→ 買い切り480円で全ルート解放。または完全無料でレビュー・口コミを集め、ブログ/SEOサイトとの連携で広告収益

**リスク・注意点:**
- 各国の検疫ルールは頻繁に改正される（2026年4月にEUルール変更あり）。コンテンツのメンテナンスコストがかかる
- 市場規模が小さいため、月3万円を達成するには英語版のグローバル展開が必須になる可能性
- 「無料の公式情報がある」ため、有料化の正当性を伝えるUI設計が重要
