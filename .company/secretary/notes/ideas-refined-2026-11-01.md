# アイデア精査レポート — 2026-11-01

## 総評

今回の収集で最も際立ったのは「法的義務化という外部ドライバー付き」の運送業界向けSaaSと、オーナーの業界インサイダー優位性の組み合わせ。英語添削周辺はEigoCheckの延長線上として低リスクな横展開候補が複数存在する。ペット渡航はニッチ需要は確かだが情報鮮度維持コストの課題がある。

## 🥇 第1位: 傭車管理シンプルアプリ（中小運送会社向け）

**総合スコア: 84/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 16/20 | SwiftUI + Supabase（REST API）で実装可能。CRUD操作が中心でアーキテクチャは単純。デジタコ連携は不要にすればMVPは3ヶ月以内に完成できる |
| 市場規模 | 15/20 | 傭車を利用する中小運送会社は国内数万社規模。ただし法人営業が必要でリーチに時間がかかる点は注意 |
| 競合の少なさ | 19/20 | App Storeで2〜3件。いずれも大手向け高額か汎用スプレッドシート。「中小向け・シンプル・安価」の空白が明確 |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層は全く異なる。スキル（SwiftUI・API連携）は流用可能だがコード・ユーザー基盤の直接流用は難しい |
| マネタイズ可能性 | 26/20→20/20（満点上限） | 月5,000〜1万円×20社=月10〜20万円が6ヶ月以内に現実的。法的義務が強い導入動機。業界インサイダーなのでユーザーインタビューが競合より深くできる |

**なぜ今のオーナーに向いているか:**
- 運送業界インサイダーとして傭車業務・実運送体制管理簿の内容を既に理解している → ドメイン知識習得コストがゼロ
- 2025年4月法改正（実運送体制管理簿の義務化）直後のタイミング → 「法律で必要だから入れなければ」という需要が今まさに顕在化中
- 競合のLogiOSが2027年前半リリース予定 → 2026年内MVPなら先行者優位を確保できる
- SwiftUIのCRUD + Supabase構成はEigoCheckで培ったスキルが直接活きる

**MVP設計案:**
- 最小機能: ①傭車先会社マスタ ②便×傭車先の割り当て記録 ③実運送体制管理簿のPDF出力 ④月次精算レポート
- 技術スタック: SwiftUI（iOS）+ Supabase（PostgreSQL REST API）+ PDFKit（Apple標準）
- 想定工数: 設計2週間・実装6週間・テスト2週間 = 計10週間（2.5ヶ月）
- 最初の収益化方法: 月額5,000円（10台以下）/ 月額1万円（11〜50台）。初月無料トライアル付き。まず現在の職場または取引先に無料で使ってもらいフィードバック収集

**リスク・注意点:**
- 法人営業は個人開発者にとってBtoCより難しい。最初の顧客獲得経路が課題（現在の職場コネクションを活用できるか）
- 運行管理システム・デジタコとの連携を求められる可能性がある（MVP段階では「連携なし」を明確に謳うこと）
- 法令変更に追随するメンテナンスコストが継続的に発生する

## 🥈 第2位: ペット海外渡航チェックリスト＆書類管理アプリ

**総合スコア: 72/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | SwiftUI のみで完結。ルートマスタ（国×ペット種）+ チェックリスト + リマインダー + 書類写真保存。複雑なAPI不要 |
| 市場規模 | 12/20 | 年間数万件規模の需要はあるが、頻度が低い（1人が使うのは1〜2回）。リピートが見込みにくい |
| 競合の少なさ | 19/20 | App Storeでほぼ0〜1件。競合サイトは情報散在・古い。アプリとして存在しないに等しい |
| EigoCheckとの相乗効果 | 8/20 | ユーザー層は異なるが、「手続きの英語書類を書く」場面でEigoCheckへの送客が可能（クロスプロモーション）|
| マネタイズ可能性 | 15/20 | 買い切り600〜900円か、特定ルートへの追加コンテンツ課金。月額は合わない（利用頻度が低すぎる）。6ヶ月で月3万円は現実的 |

**なぜ今のオーナーに向いているか:**
- 実装が最もシンプル（SwiftUI完結・外部API不要）でMVP製作の練習にも最適
- 競合ゼロ地帯でApp Store最適化が有効に機能する
- EigoCheckとクロスプロモーションできる（「英語の書類が必要です → EigoCheckで添削」）

**MVP設計案:**
- 最小機能: ①渡航ルート選択（日本→ハワイ/米国/オーストラリアの3ルート）②ペット種選択（犬/猫）③チェックリスト表示 ④手続き期限のリマインダー通知 ⑤書類写真の保存
- 技術スタック: SwiftUI + UserNotifications + PhotosUI + CloudKit（写真バックアップ）
- 想定工数: 設計1週間・コンテンツ作成2週間・実装5週間・テスト1週間 = 計9週間
- 最初の収益化方法: 基本3ルート無料 + 追加ルート（シンガポール・EU・カナダ等）を買い切り150〜200円/ルートでアプリ内課金

**リスク・注意点:**
- 各国の検疫ルールは頻繁に変更される → コンテンツ維持コストが継続的に発生
- 頻度が低いため口コミ拡散に時間がかかる（ASO と「ペット 海外」系ブログへのPRが重要）
- 間違った情報を提供すると入国拒否・隔離リスクにつながるため、免責事項の設計が必要

## 🥉 第3位: EigoCheck拡張 — 「修正理由の語彙・文法タグ付き学習ログ」機能

**総合スコア: 71/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 17/20 | 既存EigoCheckの拡張。キーボード拡張→修正→タグ分類→学習ログ。Claude APIの出力をパースするロジックが追加工数。2ヶ月以内に追加機能として完成可能 |
| 市場規模 | 14/20 | 既存EigoCheckユーザーへの追加価値提供。新規ユーザー獲得にも寄与。英語学習×キーボード市場は成長中 |
| 競合の少なさ | 14/20 | 「日本語説明付き添削」ではGrammary・Eng-Helperが先行。ただし「学習ログ×タグ分類×弱点分析」の組み合わせは競合少ない |
| EigoCheckとの相乗効果 | 20/20 | 完全に既存ユーザー基盤・コード・スキルを活用。新規開発より低コスト高リターン |
| マネタイズ可能性 | 6/20 | プレミアム機能として追加できるが、既存プランへのアップセルであり独立した月3〜10万円は難しい。EigoCheckの成長に依存 |

**なぜ今のオーナーに向いているか:**
- 既存EigoCheckの改善なので技術リスクが最小
- 収益化はEigoCheckのプレミアム課金率を上げる形で実現
- 競合アプリ（Grammarly等）が「なぜ修正されたか」の説明が弱い点を突ける

**MVP設計案:**
- 最小機能: 修正箇所に「時制」「語順」「冠詞」「前置詞」等のタグを自動付与 + 週次の「よくあるミスパターン」レポート
- 技術スタック: 既存EigoCheckコードベース + Claude API（タグ分類プロンプト追加）
- 想定工数: 設計1週間・実装4週間・テスト1週間 = 計6週間
- 最初の収益化方法: 月額プレミアムプランの新機能として追加（既存無料ユーザーのアップセル）

**リスク・注意点:**
- EigoCheckの既存ユーザー数が少ないうちは収益インパクトが小さい
- Claude APIの利用コストが増加（タグ分類の追加トークン）
