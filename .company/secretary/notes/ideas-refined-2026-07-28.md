## 🥇 第1位: ペット海外渡航ガイドアプリ（国×ペット種別チェックリスト自動生成）

**総合スコア: 82/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 18/20 | 静的JSONデータ（国別手続き一覧）＋SwiftUIのみ。API依存なし。通信機能不要なオフラインアプリとしてMVP完成可能。Custom Keyboardより技術難易度が低く、EigoCheckで培ったSwiftUIスキルが直接流用できる |
| 市場規模 | 14/20 | 海外移住・留学・赴任帯同でペットを連れて行くユーザーは毎年一定数いる。ただしニッチ。日本語ユーザー限定市場は小さめ。英語版を追加すれば英語圏の海外移住者にも刺さる |
| 競合の少なさ | 19/20 | App Storeで「ペット 海外渡航」で検索しても直接競合はほぼゼロ。農水省サイト・個人ブログのみで、アプリ形式の競合は確認できず |
| EigoCheckとの相乗効果 | 12/20 | ユーザー層が異なるため直接の相乗効果は低め。ただし「情報をわかりやすく整理して届ける」というプロダクト思想は共通。スキル流用は高い |
| マネタイズ可能性 | 19/20 | 買い切り480〜980円 or フリーミアム（基本無料・国別詳細レポートを都度課金120〜250円）モデルが最適。渡航代行業者（行政書士・ペット輸送会社）へのアフィリエイトも可。失敗したくないユーザーは課金に前向き |

**なぜ今のオーナーに向いているか:**
競合ゼロ×実装シンプル×課金意欲のある切実なニーズという三拍子が揃っている。SwiftUIのリスト・フォーム・チェックリストUIはEigoCheckで鍛えたスキルが直接使える。APIゼロ（静的データのみ）でも最初のバージョンが成立するため、ランニングコストがかからない。農水省などの公式データを元に作れるため「ライセンス不要」条件を完全クリア。

**MVP設計案:**
- 最小機能: ①出発国・到着国・ペット種（犬/猫）を選択 → ②必要書類リスト・タイムライン（〇週間前に何をすべきか）を自動表示 → ③チェック済みマーク機能
- 技術スタック: SwiftUI + ローカルJSON（国別データ） + UserDefaults（チェック状態保存）
- 想定工数: データ収集（主要10ルート）2週間、実装4週間、テスト・申請2週間。計2ヶ月以内
- 最初の収益化方法: App Store 買い切り480円。または無料＋「詳細レポートPDF生成」を120円の追加課金

**リスク・注意点:**
- 法律・渡航情報は変わりやすい。農水省ルール変更があった際にデータ更新作業が発生する（定期メンテが必要）
- ニッチすぎてダウンロード数が頭打ちになる可能性。英語版を追加することで市場が10倍以上になる
- 書類の詳細は「国ごと」かつ「年ごとに変わる」ため、情報の鮮度管理が課題

## 🥈 第2位: AIキーボード型 英語ビジネスライティングコーチ（EigoCheck次世代版）

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 15/20 | Custom Keyboard ExtensionはEigoCheckで既存実装あり。OpenAI API連携も経験済み。「ビジネスモード切り替え」「修正理由の日本語解説」UIの追加が主な追加工数。EigoCheckのv2〜v3として実装できる |
| 市場規模 | 17/20 | 英語でメール・Slack・レポートを書くビジネスパーソンは日本に数百万人以上。学習者市場よりビジネス利用市場の方が課金単価が高い |
| 競合の少なさ | 13/20 | Grammarlyが強いが「日本語で修正理由を解説する」「ビジネス文書モード特化」「日本人の英語ミスパターン特化」の3軸で差別化余地あり。直接競合は3〜5件 |
| EigoCheckとの相乗効果 | 20/20 | EigoCheckそのものの進化形。既存コード・API連携・ユーザーベース・レビューデータが完全流用できる。新規開発でなくアップデートとして展開できる最強の相乗効果 |
| マネタイズ可能性 | 14/20 | フリーミアム（月5回無料→月額980円）モデルが現実的。ビジネス利用者は月額980〜1,980円に抵抗が少ない。ただしGrammarlyの無料版と差別化できるかが鍵 |

**なぜ今のオーナーに向いているか:**
EigoCheckで蓄積したCustom Keyboard実装経験・OpenAI連携・日本人向けUX設計が全部使える。新規アプリを作るよりも既存アプリを磨く方が収益化が早い。ユーザーレビューから「なぜ修正されたか分からない」という具体的な改善ポイントが見えており、何を作ればいいかが明確。

**MVP設計案:**
- 最小機能: ①モード切り替えUI（カジュアル/ビジネスメール/Slack/レポート）②修正箇所の日本語解説を追加③添削履歴ダッシュボード（月ごとにどんなミスが多いか）
- 技術スタック: 既存EigoCheckコード + OpenAI GPT-4o（システムプロンプトをモード別に変更）+ Core Data（履歴保存）
- 想定工数: モード追加UI 1週間、日本語解説プロンプト設計2週間、履歴ダッシュボード2週間。計1〜1.5ヶ月
- 最初の収益化方法: EigoCheck Proプランとして月額980円のサブスクリプション追加

**リスク・注意点:**
- Grammarlyが日本語UXを改善してくると一気に競合が激化するリスク
- GPT-4oのAPI費用がユーザー増加とともにかさむ。月額課金設計でコスト管理が必須
- 「英語学習者」と「ビジネス利用者」でターゲットが微妙にずれるため、アプリのポジショニングを明確にすることが重要

## 🥉 第3位: 傭車管理シンプルアプリ（中小運送会社10〜50台向け）

**総合スコア: 68/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 14/20 | SwiftUI + Firebase（または Supabase）でのCRUD中心。技術的には中級レベルで3ヶ月MVP可能。ただし「月末請求照合」機能はPDF生成・Excel出力が必要で工数がかさむ |
| 市場規模 | 16/20 | 全国の中小運送会社（10〜50台規模）は数万社規模。月5,000〜30,000円の課金が見込めれば十分な市場 |
| 競合の少なさ | 18/20 | 傭車管理に特化したアプリはほぼゼロ。配車総合システムの一機能として埋もれているか、紙・Excel運用のみ |
| EigoCheckとの相乗効果 | 4/20 | ユーザー層・スキルセット・コードの流用は皆無に近い。完全な新規ドメイン |
| マネタイズ可能性 | 16/20 | BtoBなので月額10,000〜30,000円の設定が可能。5社獲得で月5〜15万円。ただし営業が必要 |

**なぜ今のオーナーに向いているか:**
業界インサイダーとしての現場理解が最大の武器。「傭車の精算に毎月5時間かかっている」という痛点を実体験で知っている。競合がほぼゼロの空白市場。ただし「EigoCheckとの相乗効果ゼロ」「BtoB営業が必要」という点で、他の2案と比べるとハードルが高い。

**MVP設計案:**
- 最小機能: ①便ごとに傭車会社・車両・運転手・運賃を記録 ②月末に傭車会社別の請求金額を自動集計 ③PDF/CSV出力で照合資料として使える
- 技術スタック: SwiftUI + Firebase Firestore + PDFKit（iOS標準）
- 想定工数: データモデル設計1週間、基本CRUD UI 3週間、PDF出力2週間、テスト2週間。計2〜2.5ヶ月
- 最初の収益化方法: 月額5,000〜10,000円（フリートライアル1ヶ月）。業界人脈で最初の3〜5社を獲得

**リスク・注意点:**
- BtoB販売は「作れば売れる」ではない。最初の1社を獲得するための営業活動がボトルネック
- 導入後のサポート・問い合わせ対応がソロ開発者には重荷になりやすい
- 運送業界は人間関係・信頼が重視される。知らない個人開発者のアプリを導入するハードルが高い
