**なぜ今のオーナーに向いているか:**
EigoCheckで培ったSwiftUI×Claude API開発の経験が100%活きる。新しい技術スタックを学ぶ必要がほぼゼロで、ユーザー価値設計（英語ライティングの即時フィードバック）に集中できる。また英語学習者という既知のユーザー像に対して、「書いた英文が蓄積されて成長が見える」という未充足ニーズを埋める形になる。

**MVP設計案:**
- 最小機能:
  - 日付別の英語日記入力画面（1日1エントリ）
  - 「添削する」ボタン → Claude APIで即時添削＋改善提案
  - 過去の日記一覧と添削履歴
  - 連続記録日数カウンター（継続モチベーション）
- 技術スタック: SwiftUI + CloudKit（同期） + CoreData（ローカルキャッシュ） + Anthropic Claude API
- 想定工数: 6〜8週間（UI設計2週 / API連携・DB設計2週 / 磨き込み・審査2週）
- 最初の収益化方法: フリーミアム（月10件添削まで無料） + 月額480円のサブスク。EigoCheckのApp Store内にバナー表示でクロスプロモーション

**リスク・注意点:**
- APIコストがユーザー増加に比例して増える。1添削あたりの上限トークンを設定し、コスト上限を管理する設計が必須
- 英語学習アプリは競争が激しくASO（App Store最適化）が重要。「英語日記」「英作文 添削」等のキーワード設計に初期コストをかける必要がある
- 「書き続けてもらう」ことが価値の源泉なので、通知・ストリーク機能のUX設計が生命線

| 評価軸 | スコア | コメント |

| 市場規模 | 15/20 | 全国の個人塾・家庭教師は数万〜十数万人規模。全員が月謝管理・成績記録の課題を持つ。日本語専用なので海外展開は不要 |
| 競合の少なさ | 17/20 | 日本語iOS専用アプリは5件以下。Web専用ツール（高価・多機能）と紙・Excelの間にある「シンプルなスマホアプリ」の空白が存在する |
| EigoCheckとの相乗効果 | 8/20 | 直接の技術・ユーザー流用は難しい。ただしApp Store申請フロー・課金実装（StoreKit 2）のノウハウは活きる |
| マネタイズ可能性 | 17/20 | 月額980〜1,980円のBtoBサブスク。一度導入されると解約しにくい（生徒データが蓄積される）。初期30社獲得で月3〜6万円 |

**なぜ今のオーナーに向いているか:**
業務フローが明確でユーザーリサーチが容易（身近に個人塾・家庭教師がいれば5分で本当のニーズを聞ける）。EigoCheckとは別軸のBtoBラインとして収益を多様化できる。「小さく確実に稼ぐ」という目標に対して、BtoBの解約しにくい特性がマッチしている。

**MVP設計案:**
- 最小機能:
  - 生徒登録（名前・学年・科目・月謝）
  - 出席記録（日付・授業時間のタップ入力）
  - 月謝管理（月ごとの請求状況・入金確認）
  - 月謝請求書PDF出力（PDFKit）
- 技術スタック: SwiftUI + CloudKit（複数端末同期） + PDFKit（請求書）
- 想定工数: 8〜10週間（要件定義1週 / DB設計・基本CRUD3週 / PDF出力・請求管理3週 / 磨き込み2週）
- 最初の収益化方法: 生徒5人まで無料 → 月額980円（制限なし）。教育系コミュニティ（Facebook・X）への投稿で初期獲得

**リスク・注意点:**
- 個人塾の場合、生徒データ（未成年の成績情報）を扱うため、プライバシーポリシー・データ保管方針を丁寧に作成する必要がある
- 初期ユーザー獲得がEigoCheckより難しい（ターゲットが全く異なる）。教育系SNSコミュニティへのアプローチが必要
- 月謝や成績に関わる「間違いが許されない」業務なので、バグへの許容度が低い。リリース前に十分なテストが必要

## 🥉 第3位: ペット渡航チェックリスト + 手続きガイドアプリ

**総合スコア: 71/100**

| 評価軸 | スコア | コメント |
|--------|--------|----------|
| 実装難易度 | 19/20 | SwiftUIのみで完結。手続きデータはJSONで管理しアプリ内に内包するか小規模なCMSで更新。技術的な難易度は今回の候補の中で最低。1〜2ヶ月でMVP可能 |
| 市場規模 | 12/20 | ニッチ。日本から海外に犬猫を連れて行く人は年間数万〜十数万件規模。大規模ではないが「行政書士に5〜10万円払う」ユーザーが存在し課金意欲は高い |
| 競合の少なさ | 19/20 | 「国別×ペット種別の手続きチェックリスト」に特化したiOSアプリはほぼ存在しない。既存は農水省PDFと行政書士のブログのみ。完全なブルーオーシャン |
| EigoCheckとの相乗効果 | 7/20 | 直接の連携は薄い。App Store審査・課金実装のノウハウ程度。ユーザー層は全く異なる |
| マネタイズ可能性 | 14/20 | 買い切り980〜1,480円が現実的。ただし月3〜10万円を6ヶ月以内に達成するには月200〜700DL必要。ニッチすぎてASO集客が難しい可能性がある |

**なぜ今のオーナーに向いているか:**
技術難易度が最も低く、コンテンツ整備（各国の手続き一覧）に集中できる。2026年EUルール改定で情報需要が急増しているタイミングが追い風。「誰も作っていない」という競合優位が明確で、検索流入でのオーガニック獲得が期待できる。

**MVP設計案:**
- 最小機能:
  - 出発国（日本固定）× 渡航先国の選択
  - ペット種別（犬/猫）の選択
  - 国別の手続きチェックリスト（タップで完了マーク）
  - 期限カウントダウン（抗体検査後180日 等）
  - 各手順の解説テキスト
- 技術スタック: SwiftUI + ローカルJSONデータ（国別手続きDB） + UserDefaults（チェック状態保存）
- 想定工数: 4〜6週間（コンテンツ収集・整理2週 / UIとDB実装2週 / 磨き込み1〜2週）
- 最初の収益化方法: 日本→主要5カ国（米・豪・英・EU・加）まで無料 → 買い切り980円で全カ国+期限通知機能。ペット関連ブログへのPR・X投稿での口コミ

**リスク・注意点:**
- 各国の規制は頻繁に改定される。情報の陳腐化が最大リスク。年2〜4回の内容確認が継続的に必要
- ユーザー数がニッチなため、月3〜10万円達成に時間がかかる可能性がある。「副業の副業」として位置づけるなら問題ないが、EigoCheckと比べてビジネスポテンシャルは小さい
- App Storeのサブカテゴリ（旅行 or ペット）での露出が限られる。SEO的な位置づけはWebサービス版（Next.js）の方が有効かもしれない
